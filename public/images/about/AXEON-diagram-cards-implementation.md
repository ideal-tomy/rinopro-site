# AXEON｜「支援を始める前に」図解入りカード 実装指示書

## 依頼内容

半内製化（FDE）ページの「支援を始める前に」セクションを、添付の比較画像の **③「図解入りカード」** に変更してください。

見本の5案を混ぜず、③だけを再現してください。見本の小さな「③ 図解入りカード」という比較用ラベルは、実際のページには表示しません。

対象はこのセクションのみです。「自社で進める際の課題」など、他セクションは変更しません。

## 見本と優先順位

実装時、この指示書と一緒に「支援を始める前に｜5つのデザイン比較」の画像を渡してください。その中の③が見本です。

- 見本画像：この会話で生成した `exec-15950e0b-2c47-49d5-8726-48a5163ba29d.png`。
- 優先順位：ユーザーの明示指示 → 本書の仕様 → 比較画像の③ → 既存スタイル。
- 見本は、PCで白いカードが5枚横に並び、上半分に内容別の図解、下半分に見出しと説明を置く構成です。
- 見本の図解内の細かな文字には生成の乱れがあります。文字は本書の指定を使ってください。
- 数値とカラーは、生成画像から取得した実測値ではなく、忠実な再現に向けた実装基準です。
- 見本が実装環境にない場合は、その旨を報告してください。「画像を確認した」とは言わず、本書の仕様を基準に進めてください。

## 完成時の見た目

淡い青灰色のセクション背景に、白いカード5枚を同じ高さで横並びにします。

カードごとに異なる図解を設置してください。汎用アイコンを1個置くだけの構成に戻してはいけません。

図解は、次の5つを見て区別できる状態にします。

1. 社内と外部の役割分担
2. 担当する人と使える時間
3. 手順を複数の人に共有
4. システムとデータの接続
5. 自社と開発会社の役割分担

これらは確認事項です。工程順を意味する番号、ステップ、カード間の矢印は設置しません。

## 変更・削除する既存要素

- 既存のアイコン付き選択タブ5枚を、図解入りカード5枚へ置き換える。
- 選択状態として付いている青い枠、下辺の青い線を削除する。
- カードの下にある、選択内容を表示する横長の説明パネルを削除する。
- 説明パネルの左側の色線と、大きな薄いアイコンも削除する。
- 説明は各カード内に常時表示する。
- 既存のセクションIDとページ内リンク先は維持する。
- クリック切り替え、反転、アコーディオン、選択状態、別パネルへの内容表示は不要。
- 操作のないカードに、ボタンの役割やポインターカーソルを付けない。

## 掲載テキスト：そのまま使用

### セクション

見出し：**支援を始める前に**

導入文：現在の体制や業務に合わせて、担当する範囲と進め方を確認します。

### 5枚のカード

| 順序 | 見出し | 説明 |
|---|---|---|
| 1 | 社内の担当範囲 | 社内と外部の担当を確認します。 |
| 2 | 担当者と時間 | 担当する人と使える時間を確認します。 |
| 3 | 知識と手順 | 操作方法と対応手順を共有します。 |
| 4 | 開発・運用の環境 | 今あるシステムと必要な環境を確認します。 |
| 5 | 開発会社との分担 | 依頼する範囲と社内の判断を整理します。 |

見出しの前に英語ラベル、小見出し、番号を追加しません。説明を営業的なコピーへ書き換えません。

| セクション上下余白 | 64px |
| 見出し | 32px、700、行高1.4 |
| 導入文 | 16px、行高1.75 |

| カード枠・影 | なし |

カードの高さは内容に合わせて決まるようにし、行全体は一番高いカードに揃えます。固定高さで本文を切りません。

## 図解の共通仕様

### 実装方法

図解はSVGとHTML/CSSで再現してください。生成画像をカード全体の背景として貼り付ける方法は使用しません。

- 人物、時計、パソコン、書類、データベースはSVGで描く。
- 図解内のラベルは、可能な限りHTMLの文字として配置する。SVGのtextを使う場合も、画像への文字焼き込みは行わない。
- 図解は、見本に近い青系のフラットな面で描く。必要なところにオレンジを使用する。
- 人物は顔の細部を省いた上半身の図形。写真、絵文字、顔写真は使わない。
- 青一色の線画アイコンを大きく置くだけの代替は禁止。
- ガラス加工、光沢、3D、強いグラデーション、発光、立体的な影は追加しない。
- 図解内部の接続線、時計の目盛り、書類の線、機器の輪郭は使用してよい。
- 図解用ラベルは12〜13pxを基準とする。主要な説明は必ずカード本文で読める状態にする。
- 図解が装飾扱いの場合はアクセシビリティ上重複して読ませない。内容を持たせる場合は簡潔な代替説明を設定する。

### カード1：社内の担当範囲

図解領域を、左右の2つの面で構成します。

**左：社内**
- 淡い青の面。
- 「社内」のラベル。
- パソコンを使う青い人物。
- 下に「日々の操作」「設定変更」の2項目。

**右：外部**
- 淡いオレンジの面。
- 「外部」のラベル。
- パソコンを使う人物。服や機器は青系、ラベルと補助色にオレンジ。
- 下に「システム開発」「機能追加」の2項目。

両方の面は等幅・同じ高さ。面そのものを色分けし、左辺だけの色線は使いません。

図解は役割の一例を示すものです。この分担をすべての契約に適用するような説明を追加しないでください。

### カード2：担当者と時間

左に人物、右に時計を並べます。

- 人物は、ネイビーの服を着た青系の上半身。
- 時計は白地に青い外周と目盛り。
- 時計の針の一方にオレンジを使用する。
- 人物の下：「担当者」
- 時計の下：「使える時間」
- 人物と時計の上端・下側ラベル位置を揃える。
- カレンダーの単独アイコンへ置き換えない。
- 特定の日付や時間数は書かない。

### カード3：知識と手順

上に操作マニュアル、下に3人を配置します。

- 上中央に書類。見出し「操作マニュアル」。
- 書類内には、青い短い線を3〜4本。
- 書類から下の3人へ、3本の細い青い接続矢印。
- 左右の人物は青、中央はオレンジ。
- 人物の下のラベルは、左から「担当者」「他の担当者」「運用担当」。
- 複数の人が同じ手順を確認できる関係が見えるようにする。
- 本のアイコン1個への置き換えは禁止。

### カード4：開発・運用の環境

左にモニター、右にデータベースを配置します。

- モニターは青い外形、淡い青の画面。
- 画面内に「システム」。
- 右のデータベースは、青系の円柱を2〜3段で描く。
- モニターからデータベースへ、短い青い接続矢印。
- データベースの下に「データベース」。
- 2つの機器の大きさを釣り合わせる。
- 歯車アイコン1個への置き換えは禁止。
- クラウドやセキュリティなどの追加要素を勝手に増やさない。

### カード5：開発会社との分担

カード1と同じく、左右の2つの面で構成します。ただし、人物は各側2〜3人のグループとし、カード1との差を出します。

**左：自社**
- 淡い青の面。
- 「自社」のラベル。
- 青い人物グループ。
- 下に「業務の確認」「社内の判断」の2項目。

**右：開発会社**
- 淡いオレンジの面。
- 「開発会社」のラベル。
- オレンジの人物グループ。
- 下に「設計・開発」「技術対応」の2項目。

一人とパソコンの図解をカード1からそのままコピーしません。自社と開発会社という組織同士の分担を見せます。

## 縁取りに関する厳守事項

**カードや説明領域の一部分だけを縁取る装飾は絶対に使用しません。**

禁止：
- 左辺だけ青・オレンジの線
- 上辺、下辺だけの強調線
- L字の線、角だけの線
- 部分的な外枠
- 選択カードだけの色付き枠
- カード内にさらに装飾用の枠を重ねる
- 見出しの下の飾り線

カードは白い面と周囲の背景色の差で区別します。

図解の中で意味を持つ「機器の輪郭」「時計」「書類の線」「接続矢印」は装飾用の縁取りと区別し、必要なものだけ使ってください。

## スマホ・狭い画面

### スマホ

縦に5枚積み上げる表示にはしません。図解カードを横スクロールで表示します。

- カードの外幅：スクロール領域の約86%。
- 1枚目を左側のコンテナ余白に揃える。
- 右側に次のカードが20〜32px程度見える構成。
- カード間隔：12px。
- カード内余白：20px。
- 図解領域：高さ160pxを基準。
- 見出し：20px、700、行高1.5。
- 本文：16px、行高1.7。
- スクロールスナップはカード単位。
- カード内の本文は常時表示。
- 自動スライド、自動反転、hover依存の操作は追加しない。
- カード内だけの縦スクロールは禁止。
- 内容が増える場合は自然に高さを伸ばす。
- スワイプ以外に左右ボタンを用意し、キーボードでも移動できるようにする。ボタンはカードの外に置く。
- 現在位置は「1 / 5」のような簡潔な表示で確認できるようにする。表示は実際の位置と同期。
- ページ全体には横スクロールを発生させない。

### 中間幅

5列に詰めるとカードの外幅が210px未満になる幅では、横スクロールへ切り替えます。

中間幅は、カードの外幅240〜280pxを基準にし、複数枚が見えるようにしてください。画面幅だけで無理に5列を維持しません。

## 改行・文字幅

- タイトル、本文に、見た目だけを理由にbrを追加しない。
- テキストに独立したmax-width、ch指定、パーセント幅制限を重ねない。
- カードの内側の使用可能幅を使う。
- 右側だけ余分なpaddingを付けない。
- 文字列全体のnowrapは禁止。長いタイトルは自然に折り返す。
- 日本語にword-break: break-allを一律適用しない。
- フォントを小さくして1行に押し込まない。
- 本文の途中で「担当する／人」のような不自然な折り返しが目立つ場合は、まずカード幅と余白を確認する。
- どうしてもタイトルの意味単位を保つ必要がある場合のみ、短い語句をまとまりとして扱う。320px幅や文字拡大でのはみ出しも確認する。
- 図解内ラベル以外の本文を画像に含めない。

## 実装の進め方

1. 対象ページと既存セクションを確認する。
2. 使用している共通コンテナ、フォント、ページ内リンクの仕組みを確認する。
3. このセクションの旧タブと説明パネルを置き換える。
4. 5種類の図解を、内容別のSVG／HTMLとして作成する。
5. PCとスマホのレイアウトを実装する。
6. 実際のブラウザで表示し、比較画像の③と見比べる。
7. 大きさ、余白、文字、図解の構成が異なる箇所を修正する。
8. 実装内容と確認できた画面幅を簡潔に報告する。

既存の技術構成に合わせて実装してください。新しいUIライブラリやアイコンパッケージを、このセクションのためだけに追加しません。

同じ余白・文字の基準は共通化してよいですが、5種類の図解を単一の汎用アイコンで代替しないでください。
