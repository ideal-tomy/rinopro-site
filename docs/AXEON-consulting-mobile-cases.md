# AXEON コンサルティング：スマホ相談例の横スライド化

## 依頼

既存コンサルティングページの「相談例」セクションを、スマホでは横スライドのカードで表示してください。

PCのタブ表示・文言・デザインは維持します。変更対象は相談例のスマホ表示と、それに必要な局所的な実装だけです。他のセクションや半内製化ページは変更しません。

現在のスマホ表示は、タイトルが3行程度に折り返され、重複する状況説明が続くため、確認事項や結論まで読むのに縦スクロールが必要です。横スライド化とスマホ向けの文章短縮で、1枚のカード内に相談の要点と結論を収めます。

以前の「相談例をスマホでも3つのタブで表示する」という指示より、この指示を優先してください。

## 1. PCとスマホの切り替え

- 既存の相談例コンポーネント、データ、ブレークポイントを確認してから変更してください。
- 既存のSP切り替え基準を優先し、基準がない場合は768px未満をカード表示にします。
- PCは現在の3つのタブと、その下の詳細パネルを維持します。
- SPは3つのタブを表示せず、3つの相談例を横に並べたカードにします。
- 相談例の順序は「部門間の二重入力」「AI導入の検討」「既存システムの見直し」。
- PCとSPの情報は共通のデータにまとめ、SP用の短い文言を別フィールドとして保持できます。PCの文言を短縮文で上書きしないでください。
- 非表示側のタブやボタンが、キーボード・支援技術で操作対象として残らないようにします。

## 2. スマホのカード構成

カード内は以下の順序にします。

1. 小さい相談分類
2. 太い相談タイトル
3. 「確認・比較すること」と短い説明
4. 「まとめる内容」と結論

SPでは次を省きます。

- 「相談の状況」のラベル
- タイトルと同じ内容を言い直す状況説明の段落
- タイトル下の装飾線や、内容の理解に不要な大きな余白
- カードごとに重複する検討例の注記

「確認すること」と「比較する対応方法」は、SPでは「確認・比較すること」に統合します。要点を短くまとめますが、結論は必ず初期表示で読めるようにしてください。

## 3. SP専用の掲載文

以下の文言を使用してください。PC側は現在の文言を維持します。

### カード1

相談分類：

> 部門間の二重入力

タイトル：

> 同じ情報を何度も入力している

確認・比較すること：

> 重複する入力を確認し、システム連携・業務変更・入れ替えを比較します。

まとめる内容：

> 変更する範囲と、先に取り組む業務

### カード2

相談分類：

> AI導入の検討

タイトル：

> AIをどの業務に使うか決めたい

確認・比較すること：

> 使う情報と確認作業を整理し、AI・既存ツール・手順変更を比較します。

まとめる内容：

> 試す業務の範囲と、効果の確認方法

### カード3

相談分類：

> 既存システムの見直し

タイトル：

> 今のシステムをどこまで変えるか

確認・比較すること：

> 利用状況や移行の制約を確認し、入れ替え・部分変更・機能追加を比較します。

まとめる内容：

> 残す部分と変更する部分、移行の順番

### 共通注記

スライド全体の下に、次の注記を一度だけ掲載します。

> 相談内容に応じた検討例です。実績ではありません。

各カードの中には重複表示しません。

## 4. 横スライドのデザイン

- セクションの淡い青背景、H2「相談例」、短い青い下線は既存デザインを維持します。
- カードは白背景、淡い青の1px枠、控えめな角丸。強い影は付けません。
- 左右の外側余白は16〜20px。カード間の間隔は12〜16px。
- カード幅は画面幅の約85〜88%を初期目安とします。372px幅では約316〜327pxです。
- 初期表示で、次のカードの一部が右に見えるようにします。次カードの見切れは12〜24px程度を目安に調整してください。
- カード内余白は16〜20px。
- 相談分類は14px程度・青・太字。タイトルは20〜22px、行間1.4〜1.5、濃紺・太字。
- タイトルは標準のスマホ幅で原則2行以内を目指します。文字を小さくして無理に収めません。
- 「確認・比較すること」は14〜15px・青・太字、本文は16px・`#111111`・行間1.6程度。
- 「まとめる内容」は淡い青の背景で強調します。結論は16〜18px・太字。背景内の余白は12〜14px程度。
- 同じ行に並ぶカードの高さは最も長いカードに合わせて構いません。文字を切る固定高さは設定しません。
- 図や大きなアイコン、不要なボタンを追加して高さを増やさないでください。

## 5. 高さの目標と改行

- 添付の372×614pxの表示を基準に、セクション冒頭へスクロールしたとき、固定ヘッダーを除いた画面内で、見出し・カードの結論・位置表示まで読めることを目指します。
- セクション上余白は24〜32px、見出しとスライドの間は16〜20px、位置表示の前後は8〜12px程度から調整します。
- まず重複文・余白・行間を調整し、本文16pxを維持してください。
- 共通注記まで含めて、すべての端末で絶対に1画面に収める必要はありません。短い画面や文字拡大時は自然に縦へ伸ばします。
- `height: 100vh` 等の固定高さで文字を切らないでください。カード内に縦スクロールも作りません。
- `line-clamp`、省略記号、`overflow: hidden` で文章を隠して達成したことにしないでください。
- タイトルの改行は文章・幅・フォントサイズの調整で解決します。SP全幅で同じ位置に改行させるための大量の `<br>` は不要です。
- `word-break: normal; overflow-wrap: break-word` を基本にし、日本語を1文字ずつ分割するspanは使いません。
- 「どの業務に使う／か」のように助詞だけが次行に出る状態や、末尾1文字だけの折り返しがないか実画面で確認します。
- `text-wrap: pretty` 等は補助として利用できますが、それだけで確認済みとしないでください。

## 6. スライドの動作

- 既存の十分なカルーセル部品がある場合は再利用できます。新しいパッケージの導入は前提にしません。
- 新規実装なら、横スクロールとCSS Scroll Snapで構成できます。
- トラックに `overflow-x: auto`、`scroll-snap-type: x mandatory` を設定し、カードには `scroll-snap-align: start` を設定します。
- スワイプ後、カードの左端が外側余白にそろうように `scroll-padding-inline` 等を調整します。
- 最後のカードも所定の位置にスナップできるよう、末尾余白を確保します。
- ページ全体が横スクロールしないよう、Flex/Gridの `min-width: 0`、トラック幅、カードの `flex-shrink: 0` 等を確認します。
- 自動再生・無限ループ・勝手なスクロールは付けません。
- 通常の縦スクロールを妨げるジェスチャー制御や、不必要な `preventDefault` を追加しません。

### 現在位置

- スライド下に3つのドットと「1 / 3」を表示します。
- ドットはタップ・キーボード操作で該当カードへ移動できるボタンにします。小さい見た目でもタップ領域は44px程度を確保します。
- `aria-label` には「AI導入の検討を表示」など対象が分かる名称を付けます。
- 現在位置は実際に見えているカードと同期します。初期値のまま固定しません。
- タッチスクロール、ドット操作、画面幅変更のいずれでも状態が合うようにします。
- 必要ならトラックをrootとしたIntersectionObserverやスクロール位置から、表示領域内の主カードを判定します。高速スクロールでも番号が不安定に点滅しないようにします。
- `prefers-reduced-motion` の場合は、ボタン操作によるスムーズスクロールを無効にします。
- カードは通常の読み順で内容を読める構造にします。SP表示に、動作していないPCタブのARIA属性をそのまま流用しません。

## 7. 確認と完了条件

変更後は、既存プロジェクトに必要なビルド・型チェック等を行い、実ブラウザで確認してください。

確認幅：320px、372px、390px、430px、およびPCの1280pxまたは1440px。特に372×614pxで高さを確認します。ブレークポイント前後も確認してください。

- [ ] SPではタブがなく、3枚の横スライドカードになっている
- [ ] 初期表示で右側に次のカードが見える
- [ ] 3枚とも相談タイトル、確認・比較、結論が読める
- [ ] 標準文字サイズの372×614pxで、結論までの高さを確認した
- [ ] 本文16pxを維持し、文章を省略・切り取りしていない
- [ ] 不自然な改行、カード内縦スクロール、文字切れがない
- [ ] スワイプ後の位置がそろい、最後のカードも正しく表示される
- [ ] ドットと「1 / 3」が実際の表示カードに同期する
- [ ] ドット操作・キーボード・フォーカス表示が動作する
- [ ] 共通注記が1回だけ掲載されている
- [ ] 文字を拡大した場合は自然に高さが増え、内容が欠けない
- [ ] ページ全体に横スクロールが発生しない
- [ ] PCのタブ、文章、レイアウトを変更していない
- [ ] 他のセクションと半内製化ページに変更がない

変更ファイル、確認した画面サイズ、ビルド結果、未確認事項を簡潔に報告してください。372×614pxで3枚それぞれの実画面と、PCの相談例のスクリーンショットを提示してください。ブラウザで確認できなかった場合は、その旨を明記します。
