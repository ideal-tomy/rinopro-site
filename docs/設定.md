承認を減らす設定そのものがPowerShellを起動しているわけではないですが、承認待ちで止まらなくなった分、Codexが git、rg、powershell、cmd などのコマンドを連続実行するようになり、Windows版Codexの「子プロセスごとにコンソールが見える」不具合が一気に表面化した可能性が高いです。現在もWindows + Cursor統合ターミナルで、各shellコマンドごとにPowerShell/Windows Terminalが出る報告があります。GitHub
なので、承認設定は元に戻さなくていいと思います。代わりに、Codexの起動方法を変えるのが本命です。
まず一度、Cursorのターミナルでこれを実行してCodexを起動してください。
codex --no-daemon

--no-daemon は共有バックグラウンドサーバーを使わず、今開いているターミナル内でCodexを動かすモードです。Windowsで「git/pwshのウィンドウが毎ターン出る」問題について、これで止まったという再現報告があります。GitHub
そして重要なのが、設定ファイルに単に
[features]
daemon_auto_start = false

と書くだけでは不十分な場合があります。すでにdaemonが起動していると、そのdaemonへ再接続してしまう挙動が報告されています。--no-daemon なら既存daemonがいても確実に使わない動作になります。GitHub
一度、既存daemonも止めておくと切り分けしやすいです。
codex app-server daemon stop

その後、
codex --no-daemon

で作業してみてください。
