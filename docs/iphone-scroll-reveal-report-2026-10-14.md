# iPhoneのスクロール表示が直らない件

作成日: 2026-10-14

実機の iPhone では、一度見えた内容が消えて、もう一度ゆっくり出る現象が残っている。コンサルティングページの相談例までが、いま唯一そろって見える区間である。この文書は、いまの仕組み、ここまで入れた修正、それでも残る理由、次に直すなら何をするかをまとめたもの。

## 1. 現在の状態と構造

表示の仕組みは2系統ある。全ページの土台は1つ目で、相談例だけが2つ目になっている。

### 共通の自動表示

`src/app/layout.tsx` から、全ページに `ScrollRevealController` が載っている。ページを開いたあと、画面の高さが約150ms動かなくなるのを待ってから（最長500ms）、次の単位を拾う。

- 見出しと、その直下の導入文を1かたまり
- カードは1枚ずつ。`article`、または見出しや開閉を含む `li`
- カードの中の見出しや本文は、カードとは別に動かさない
- フッター
- ページ側で個別指定した要素（`data-scroll-reveal="target"`）のうち、上の単位に入っていないもの

画面の外にある単位は、入った瞬間に JavaScript のアニメーションで透明度を0から1へ変える。スマホは980ms、PCは760ms。すでに画面内にある本文は隠さない。

「もう出した」という印は、要素ではなくメモリ上にだけある。アドレスバーの出し入れで画面高さが変わると、対象の拾い直しが走る。

### 相談例の専用表示

コンサルティングの図と相談例だけは、HTMLの時点で `data-scroll-reveal="off"` が付いており、共通処理の対象外である。

相談例（`#consulting-examples`）は `useScrollReveal()` がセクション全体を1かたまりとして見る。画面の外にいるあいだは CSS で透明度0にしておき、スクロールで届いたら透明度1へ1回だけ変える。見出し、説明、カードは同じ動きに乗る。下からせり上がる移動はない。

```css
.section[data-reveal-ready="true"]:not([data-entered="true"]) { opacity: 0; }
```

この「届く前から隠しておき、届いたら1回出す」が、実機で理想に感じているリズムである。

### 支援内容がまだ分かれている理由

支援内容（`#consulting-support`）には `off` がなく、共通処理の側に残っている。見出しの塊が1回、その下のカードが1枚ずつ、それぞれ「見えたあとに透明度0へ落として出し直す」。相談例のような、届く前からの一括非表示ではない。

## 2. 対策として行った修正

### 1回目: 発火を1回に寄せる

対象ファイル:

- `src/lib/motion/scroll-reveal.ts`
- `src/components/navigation/ScrollRevealController.tsx`
- `src/components/services/useScrollReveal.ts`
- `src/components/services/ConsultingPage.tsx`
- `src/components/services/consulting-page.module.css`

内容:

- 画面高さが落ち着くまで、透明にするのを遅らせた
- 一度見送った親を、アドレスバーのあとから動かし直さないようにした
- コンサルティングの図と相談例を、共通処理から外した
- 計画カードの3行だけ、枠のあとに 120ms / 240ms / 360ms で出る段差を残した。遅延は表示開始前からCSSに書くようにした

ローカルのスマホ幅では、同じ要素へのアニメーション開始が2回記録されないことを確認した。この確認はアドレスバーの出入りを、画面の高さを数値で切り替えて模擬したものである。iPhone実機ではない。

### 2回目: 見出しの塊とカード1枚

`ScrollRevealController` の拾い方を変えた。見出し・本文・一覧の項目をばらばらに動かすのをやめ、見出しの塊とカード1枚を単位にした。動きは透明度だけにした。

ローカル確認では、支援内容が「見出しの入れ物1回 + カード4枚」になっていた。同じカードの中で文字だけが別アニメーションになる記録はなかった。

## 3. それでも直らない原因の考察

修正は「何を1回動かすか」と「いつ数え始めるか」を変えた。相談例と違うのは、**隠すタイミング**である。ここが残っている。

相談例は、画面の外にいるあいだ透明度0である。スクロールで届いたとき、初めて1回出てくる。見えてから消える手順がない。

共通処理は、届くまでは普通に見えている。届いた瞬間、アニメーションが透明度を0に戻し、980msかけて出し直す。実機ではこれが「見えたと思ったら消えて、もう一度出る」になる。支援内容は見出しの塊とカード4枚が別々にこれを行うので、同じ区間で連続して起きる。

さらに、出した印がメモリ上だけなので、次のときにもう一度0に戻せる。

- アドレスバーで `resize` が来るたびに、対象の拾い直しが走る
- ページ遷移や再描画でこの処理が作り直されると、印は空に戻る。進行中のアニメーションは取り消され、見えている状態に戻ったあと、また0から出し直す
- iPhone の Safari は、スクロール中にアドレスバーの高さが変わる。PCで幅を狭めても、この再スタートは起きない

そのため、PCでも、開発用ブラウザのスマホ幅でも、実機の「消えてもう一度」は再現できない。ローカル確認が通っても、実機では残る。

## 4. まだ改善するなら直す内容

可能性はある。相談例と同じ手順を、共通処理の単位にも使う。

1. 見出しの塊とカード1枚は、いまの単位のままにする。中の文字は分けない。
2. 画面の外にいるあいだは、相談例と同じく CSS で透明度0にしておく。JavaScript で「見えたあとに0へ戻す」のはやめる。
3. 届いたら透明度1へ1回だけ変える。出した印は要素自身に残す。アドレスバーが動いても、処理が作り直されても、もう隠さない。
4. 最初から画面内にある本文は、いまどおり隠さない。
5. 相談例、図、半内製化ページの専用処理は触らない。計画カード3行の段差も残す。

直す場所は `ScrollRevealController.tsx` が中心になる。速さ（スマホ980ms、PC760ms）は変えない。

この修正のあと、合格の判断は実機の iPhone Safari で行う。PCの幅変更や、高さの数値を切り替える模擬では、今回残っている現象は見えない。
