# AXEON コンサルティングページ 改修指示書

対象：`/services/consulting`
目的：添付の縦長デザインサンプルの構成・余白・配置を再現し、既存の「ご支援内容」ページと統一する。
この指示文を読んだら、既存コード・画像・共通コンポーネントを確認して実装と表示確認まで進めてください。計画の提示だけで終わらないでください。

## 1. 参照資料と優先順位

使用する参照は次の3つです。

1. この指示書：掲載文言、レイアウト数値、変更範囲の指定。
2. 添付の縦長コンサルティングページサンプル：全体構成、配置、余白のバランス、青系のビジュアル表現。
3. 既存の `/services` と `スクリーンショット 2026-10-07 012918.png`：共通ヘッダーとヒーローの統一、ヒーロー右側に使う既存画像と強調枠。

**例外：縦長サンプルのヒーロー右側にある青いイラストは使いません。現在のコンサルティングページの `services01.jpg` と、①②を囲むオレンジの強調枠に置き換えます。**

数値は生成画像から測定した既存CSS値ではなく、再現用に定めた実装基準です。既存 `/services` の共通コンテナ・ヒーローの値が取得できる場合は、その値を優先し、他の余白も同じ基準で統一してください。数値を独自の好みで変更しないでください。

## 2. 作業範囲

- 変更対象はコンサルティング詳細ページと、そのページ専用のコンポーネント・スタイル。
- トップ、`/services`、半内製化ページ、会社紹介の内容・レイアウトは変更しない。
- 共通ヘッダー・フッター・ナビゲーションは既存を再利用する。サンプルを見て新規に似たヘッダーを作らない。
- 共通CSSを変更する場合は、他ページの見た目が変わらないことを確認する。
- 本番デプロイ・公開は行わない。
- セクションやキャッチコピーを独自に追加しない。文言は以下を使用する。
- 支援実績、価格、期間、顧客情報、未確認のサービス条件を創作しない。

## 5. コンテナ・余白の基準

### PC：1024px以上

既存 `/services` のコンテナが確認できれば同じ幅・左右位置を使用。確認できない場合の基準：

| 項目 | 指定 |
|---|---|
| 本文最大幅 | 1120px |
| コンテナ幅 | `min(1120px, calc(100% - 64px))` |
| 左右配置 | 中央。1440px幅では左右160px |
| パンくず上下padding | 16px |
| ヒーロー左右padding | 32px |
| ヒーロー上下padding | 40px |
| ヒーロー2列間gap | 32px |
| 通常セクション上下padding | 56px |
| セクション見出し→説明 | 12px |
| セクション説明→カード・図 | 24px |
| 3列カードgap | 20px |
| カード内padding | 24px |
| カードタイトル→画像 | 20px |
| カード画像→説明 | 16px |
| 補足上margin | 16px |
| 関連リンクgap | 16px |

セクション間は前後のpaddingの合計で管理し、さらに大きなmarginを重ねない。背景色が切り替わる境界にも、理由のない空白帯を作らない。

### タブレット：768〜1023px

- コンテナ左右余白24px。
- ヒーローは1列に切り替え、文字→画像の順。本文と画像間24px。
- 3列カードはこの幅では維持し、gap16px・padding16px。文字のはみ出しがないこと。
- 進め方は1列。過度に長くなる補助イラストは非表示にできる。
- セクション上下padding48px。

### スマホ：767px以下

- コンテナ左右余白20px。
- ヒーローは文字→画像の1列。上下padding28px、内部padding20px、文字と画像間24px。
- セクション上下padding40px。
- 見出し→説明10px、説明→コンテンツ20px。
- カード内padding20px、内部gap16px。
- PCの3列を単純な小型3列に縮めない。
- 画面全体には横スクロールを発生させない。

## 6. 色・書体・文字

既存サイトのフォントをそのまま使用し、ページ単独で別フォントを導入しない。

| 用途 | 基準 |
|---|---|

| 本文・見出し | `#0B1730` |
| 青いリンク・ラベル | `#1D4ED8` |
| メインボタン | 既存サイトの紺色。基準 `#1E3A8A` |
| 薄青の面 | `#EEF7FF` |

| 通常カード角丸 | 12px |
| ボタン角丸 | 6〜8px、既存ボタンに合わせる |

| 文字 | PC | スマホ |
|---|---|---|
| H1 | 48px / 1.2 / 700以上 | 34px / 1.25 / 700以上 |
| ヒーローの説明見出し | 24px / 1.5 / 700 | 20px / 1.5 / 700 |
| H2 | 36px / 1.3 / 700 | 28px / 1.35 / 700 |

- 本文は左揃え。3カード内の短文はサンプル同様に中央揃えでもよい。
- 本文に改行目的の `<br>`、`white-space: nowrap` を使わない。
- H1や短い見出しは意味のまとまりを守り、画面幅に応じて自然に折り返す。
- `word-break: normal`、`overflow-wrap: break-word` を基準とし、`break-all` を常用しない。
- テキスト列に不要な `max-width: 60%`、右padding、空のグリッド列を入れない。

- 影は弱く。濃い影や枠の二重表示を追加しない。
- 数字は進め方の01〜03と資料中の必要な箇所だけに限定する。

## 7. ヒーロー：既存画像と強調枠をそのまま移す【最優先】

### 掲載する文字

英字ラベル：
> CONSULTING

H1：
> コンサルティング

説明見出し：
> 何から着手するか、実行までの道筋を整理します。

本文：
> 経営と現場の状況を確認し、課題・優先順位・進め方をまとめます。

### PCレイアウト

- `/services` と同じ、左文字・右画像のヒーロー。
- 淡い青の背景。ヒーローの外側に装飾枠や大きな角丸カードを追加しない。
- 2列は `minmax(0, 1fr) minmax(0, 1fr)`、gap32pxを基準とする。
- 文字・画像は上下中央。固定の大きな高さや `min-height: 600px` は使わない。
- 画像の情報量が多いため、右列を極端に小さくしない。
- 高さは文字と画像の実寸＋上下paddingで決める。

### 右側画像の内容

使用するのは、既存 `services01.jpg` 全体と、その上の強調表示です。

添付画像では：
- ①戦略コンサルティングの列をオレンジ枠で囲んでいる。
- ②ITコンサルティングの列を別のオレンジ枠で囲んでいる。
- 2つの枠内に淡いオレンジの色面がある。
- ③システム開発、④導入・展開、⑤運用・保守もそのまま見える。
- 下部の紺色のAXEON帯まで画像全体に含まれる。

**この状態を一体で右側へ移してください。①②だけを切り抜く、全体を1つの外枠で囲む、別イラストに置き換える、枠を青にする、画像の内容を書き直すことは禁止です。**

### 実装条件

1. 現在の画像＋枠を描画しているコンポーネントまたは要素を、できる限りそのまま移動する。
2. 枠が画像に含まれる場合は重ねて枠を追加しない。
3. 枠がHTML/CSSの場合は、画像と枠を同じ `position: relative` のラッパーに入れる。
4. ラッパーの幅は100%、画像は `display:block; width:100%; height:auto;`。画像でラッパーの高さを確定する。
5. 枠の座標・寸法は既存値を保持する。固定pxに依存する場合は元画像に対する割合に変換し、画像と一緒に拡縮させる。
6. 枠の基準は画像の表示領域。ヒーローや余白を含む親要素を基準にしない。
7. 画像を `object-fit: cover` で切り取らない。固定高さの箱に押し込まない。
8. ブラウザバーやスクリーンショット外の余白は素材に含めない。添付は枠の状態の確認用で、既存画像を優先する。
9. 現在の範囲説明「①戦略コンサルティング・②ITコンサルティングがコンサルティングの主な範囲です」が別要素としてある場合は、画像下に14pxの短いキャプションとして移動する。画像の内部へ焼き込まない。
10. モバイルでも画像と枠は同じ比率で拡縮する。枠だけPCサイズで残さない。

画像には適切なaltを設定し、装飾用の枠は読み上げ対象から外す。モバイルの画像内文字は小さくなるため、サービス範囲はページ本文でも説明する。

## 14. スクロール表示演出

- 既存トップ・`/services` の演出があれば同じ仕組み・値を再利用する。
- ない場合はセクションが画面に入った初回に、透明度0→1、下方向12px→0、800msを基準とする。
- セクション単位で表示。カード1枚ずつの長い連続待ち時間を作らない。
- ヒーローは初期表示を妨げない。
- `prefers-reduced-motion: reduce` ではアニメーションを省略。
- JavaScriptや監視処理が動かなくても内容が永久に非表示にならない。
- 演出のために要素の高さや周辺の余白を変化させない。

## 15. 素材と参考画像の扱い

- 縦長サンプル画像全体をそのまま背景画像にしてページを作らない。文字・ボタン・カードはHTMLで実装する。
- ヒーローの指定素材 `services01.jpg` は新規生成・差替え禁止。
- その他の青系イラストは、利用できる適切な素材を優先する。旧ページの紺・金イラストを色味の違うまま混在させない。
- イラストが用意できない場合、無関係な写真や大量の絵文字で埋めない。素材不足箇所を具体的に報告し、配置・余白・本文の実装は進める。
- 未用意の素材は未完了と明記し、忠実再現できたと報告しない。
- 空白を埋めるために装飾を追加しない。サンプルにある余白と、未実装による空白を区別する。

## 16. 実装後の確認と修正

表示確認は375／390／430／768／1024／1280／1440pxで行ってください。特にPCは1440px、スマホは390pxを中心に確認します。

### 最優先チェック
- ヒーロー右側が `services01.jpg` 全体＋①②のオレンジ枠になっている。
- 枠の位置・透明な色面・下部紺色帯が保たれ、画面幅を変えても枠がずれない。
- 画像が欠けず、縦横比が変わっていない。
- `/services` とコンテナの左右位置・ヒーローの書体・見出しサイズがそろっている。
- 旧セクションや旧画像が重複して残っていない。
- 全ページに横はみ出しがなく、横スクロールはカード領域だけに発生する。

### 余白・配置チェック
- セクション見出しの左端がそろっている。
- カード幅・gap・画像高さがそろっている。
- テキスト右側に不要な空列や余白がない。
- 画像の外枠とカード枠が二重になっていない。
- 意味のない大きな縦余白、空の要素、固定高さが残っていない。
- スマホの見出しが1文字だけの最終行になっていない。
- 次カードの見切れとドットが機能している。

ブラウザでスクリーンショットを取得し、サンプルと比較して余白・幅・文字サイズの差を修正してください。初回実装だけで完了にせず、確認できた差を直してください。共通ヘッダー・フッターは既存を正とし、ヒーロー素材の差替えは指定済みの差として扱います。

既存プロジェクトで必要なビルド・型チェックを実行し、変更に関係するエラーを解消してください。ブラウザ確認ができない環境では未確認と明記し、確認済みと報告しないでください。
