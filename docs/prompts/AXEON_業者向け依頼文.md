# AXEON WebサイトのUI・UX改善依頼

AXEONの既存Webサイトについて、デザインの見直しとフロントエンド実装を相談したいです。

既存リポジトリ： https://github.com/ideal-tomy/rinopro-site

## 依頼の背景

これまでAIを使いながら制作・修正を続けてきましたが、スマートフォンでの日本語の改行、余白、文字の大きさ、情報の配置が安定していません。

局所的な修正を重ねると別の箇所が崩れるため、今回は、画面の設計から実装・表示確認まで責任を持って仕上げていただける方を探しています。

文章や機能を一から作り直すことよりも、現在の内容を読みやすく、会社のサイトとして信頼できる見せ方に整えることが目的です。

## 今回お願いしたい範囲

- トップページのPC・スマートフォン表示の再設計と実装。
- ヘッダー、フッター、文字、余白、ボタンなど、主要ページで共通する表示の整理。
- 主要下層ページへの適用範囲の提案。対象ページと費用は見積もり時に明示してください。
- 既存の文章、画像、デモ、リンク、機能を活かした改善。
- 実装後のレスポンシブ表示と主要操作の確認。

既存コードを確認したうえで、活かせる部分と変更が必要な部分を判断してください。構造の整理が必要な場合は、その理由と影響範囲を説明していただきたいです。

## 重視すること

### 1. 日本語が自然に読めること

- 見出しの重要な熟語や語句が、不自然な場所で分割されないこと。
- 見出しの末尾の1〜2文字や、句読点だけが孤立しないこと。
- スマートフォンでは長い本文を原則左揃えにすること。
- 特定の端末だけに合わせた大量の強制改行を使わないこと。
- 文字を小さくするだけで問題を解決せず、幅・配置・行間と合わせて調整すること。

本文の自然な折り返しは問題ありません。すべての熟語を機械的に改行禁止にするのではなく、特に見出しの読みやすさを重視してください。

### 2. 意図の分かる余白と配置

特に気になっているのは、テキスト領域の右側に生まれる、用途の分からない大きな空白です。

- 画像がないのに2列分の領域だけ残っている、といった配置を避けること。
- コンテナ、カード、本文に幅制限や左右余白を重ね、使える幅が必要以上に狭くならないこと。
- スマートフォンで要素を非表示にした際は、その要素が占めていた空間も整理すること。
- 本文の読みやすさを保つ行幅や、見出し・画像の関係を作るための余白は適切に残すこと。

空白をすべて埋めたいわけではありません。要素同士の位置関係と、空白を設ける理由が分かる設計を希望します。

### 3. 内容に合わせたデザイン

「中央揃えの見出し、同じ形の3列カード、大きな余白」をすべてのセクションに繰り返すような、汎用テンプレート中心の構成は避けたいです。

- サービス説明、画面紹介、会社紹介、問い合わせで、それぞれの内容に適した配置を選ぶこと。
- 見出し、画像・デモ画面、CTA、補足の優先順位が伝わること。
- 意味のない番号、装飾用アイコン、二重の枠、過度な影を増やさないこと。
- 本文を薄いグレーにしすぎず、スマートフォンでも十分に読めること。
- スマートフォンをPC版の単純な縮小・縦積みにしないこと。

カードや中央揃え自体を禁止したいわけではありません。AXEONの内容に対して、その配置を選ぶ理由があることを重視しています。

## 進め方の希望

1. 現在のコードと画面を確認し、問題と改善範囲を整理する。
2. トップページのPC・スマートフォンのデザイン案を提示する。
3. 文字、余白、画像、CTAの配置を確認したうえで実装する。
4. 主要下層ページへ、合意した範囲で適用する。
5. 各画面幅と実機で確認し、指摘箇所を修正して納品する。

最初から全ページを進めず、トップページで方向性を確認したいです。デザイン確認と実装後の修正について、見積もりに含まれる回数・範囲も教えてください。

## 表示確認と納品条件

- スマートフォン幅375・390・430px、PC幅1280・1440pxを基準に確認。
- 基準幅の間でも、文字のはみ出しや不自然な配置が起きないこと。
- iPhoneのSafariと、PCのChromeで確認。確認した実機・OS・ブラウザを報告してください。
- 意図しないページ全体の横スクロールがないこと。
- 意図的な横スクロール表示は、その領域だけで操作できること。
- メニュー、ボタン、リンク、既存フォームなどの主要操作が使えること。
- キーボード操作、フォーカス表示、文字のコントラストにも配慮すること。
- 合意した文章・機能・リンクを維持すること。

納品物として、実装コード、変更内容の説明、確認した画面のスクリーンショット、運用時に必要な情報を希望します。Figma等を使用する場合は、編集可能なデータも含めてください。

本番反映は、プレビューで確認後に別途合意して進めたいです。

- 担当する方の制作実績。日本語のスマートフォン表示を確認できるものがあると助かります。
- 修正対応、納品後の不具合対応、ソースコード・デザインデータの利用条件。
