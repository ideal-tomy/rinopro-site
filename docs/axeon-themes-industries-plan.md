## 0. 役割

AXEONは中堅以上が主。入口は「何を請け、何を断るか」と「どの業界のどの仕事か」。

idealは中小〜中堅。入口は仕事の名前（建設、写真が終わらない）。記事の全文とハブはidealに置く。

ビジネスモデルは近い。見出しと最初の一手は分ける。デモのエンジンは共用する。

## 1. サイトに載せる骨格

idealの `/articles` をコピーしない。AXEONは次の2層。

### テーマ（案件基準・サービス入口）

| テーマ | 提供すること | 受けないこと |
|---|---|---|
| AI業務アシスタント | 社内規程・手順書・過去資料の検索、要約、下書き | 自律判断、根拠なしの顧客自動回答、法務・医療・融資判断 |
| 現場業務のデジタル化 | 写真整理、報告書、点検記録、引継ぎ、進捗の可視化 | 安全管理の最終判断、設備の遠隔制御、法定帳票の保証 |
| データ活用・見える化 | Excel・基幹周辺の集約、ダッシュボード、会議資料の下書き | 会計・在庫・人事など基幹記録の置き換え |
| AI導入・定着支援 | ユースケース選定、利用ルール、研修、推進チームの伴走 | AIガバナンスの適合保証、セキュリティ認証・監査の代行 |
| 業務プロセス再設計 | 属人作業の可視化、標準化、自動化候補の設計・小規模実装 | ERP刷新、基幹更改の元請け・全体責任 |

CSデモを使う場合、「顧客への自動回答は受けない」は「根拠のない確定はしない／答えられないものは人へ回す」に揃える。

### 業界（注力5。記事9本全部は出さなくてよい）

| 業界 | 課題（短く） | 支援 | 境界線 |
|---|---|---|---|
| 建設・設備 | 写真・報告・工程が分散し、現場と事務所の往復が多い | 写真整理、報告書下書き、記録検索、協力会社の情報整理 | 施工品質・安全・法令・工期の最終判断は顧客側 |
| 製造・産業機械 | 規程・図面・不具合が探せない、熟練依存、報告が重い | ナレッジ検索、品質報告の下書き、会議向けの可視化 | 設備制御、品質合否の自動判定、製品安全判断は扱わない |
| 卸売・商社・物流周辺 | 商品・在庫・見積が散在、営業事務が属人 | 問い合わせ一次整理、見積・提案下書き、情報集約、会議の可視化 | 在庫引当・受発注・配送のAI確定、決済連携は扱わない |
| 不動産・施設運営 | 物件・修繕・問い合わせが分散 | 社内検索、点検・修繕報告、問い合わせ分類、運営ダッシュボード | 賃料査定・与信・入居審査の自動判断、契約の法的判断は扱わない |
| 専門サービス・バックオフィス | 文書、社内問い合わせ、会議・報告 | ナレッジ、提案・報告の下書き、定型の自動化 | 法的見解・税務・採用合否・人事評価の自動決定は扱わない |

専門サービスは士業そのものを前面に出さない。BPO、本社管理、業界団体、採用・研修まわりを主にする。士業 Mini SFA は商談の静かな導線に留める。

介護・保育・飲食はideal記事として残す。AXEONの注力5からは外してよい。デモURLが必要なら業種LPの関連にだけ出す。

## 2. ページの置き方（案）

既存の `/industries/construction` ・ `/manufacturing` を壊さない。その上にテーマ／境界を足す。

| URL（案） | 役割 |
|---|---|
| `/services` またはテーマハブ | 5テーマ。提供／受けないを本文の主役にする |
| `/industries/{slug}` | 注力業界。課題・支援・境界・デモ・問い合わせ |
| `/contact` | テーマまたは業界をクエリで受け、境界を再掲 |

idealの `/articles/{slug}` へ「現場の読み物」でリンクしてよい。AXEON内に記事HTMLを複製しない（法令保守が二重になる）。

コピーは AXEON 表記。`strategy.md` の禁止語を守る。ideal／AXEONを本文で混ぜない。

## 3. フェーズ

### A0 文書の確定（実装の前）

- 本PLANのテーマ5・業界5・境界を、営業とサイトで同じ表にする
- 既存 [リニューアル計画.md](./リニューアル計画.md) の建設・製造2カードと、本表の「建設・設備」「製造・産業機械」を同一slugにする
- 卸売・物流は営業入口は1つ、デモは小売CS／（後追い）倉庫・運送を分ける、と注記する

### A1 テーマ＋境界をサイトに出す（idealのデモ新規を待たない）

1. テーマ一覧（提供／受けない）
2. 業界5の短いページまたは既存industryの先頭に「支援／境界」ブロック
3. 問い合わせフォームにテーマまたは業界の選択
4. 建設・製造は既存外部デモへ（idealと同じURLでよい）

この時点でAXEONは「請ける範囲が読めるサイト」になる。知識記事の全文はideal。

### A2 ideal P1のデモをAXEONから開く

idealで倉庫・運送デモが公開されたら:

- 物流周辺のindustryページから、倉庫／運送を別CTAにする（1本の「物流DXデモ」にまとめない）
- コピーは中堅向け: 既存基幹は残す、最終判断は顧客、部門で見る

シフト・ビルメンもURLが来たら施設／店舗系に接続。保育の借り物画面はAXEON注力に載せない。

### A3 不足デモ（AXEONが主導してよいもの）

idealの仕事記事より、中堅の「既存システムは残す」が見えるものが先。

| 優先 | 内容 | Won't |
|---|---|---|
| 高 | 社内ナレッジ（既存 `internal_knowledge_demo` のAXEON導線） | 法務・医療判断 |
| 中 | 見積・提案の下書き（商社を本気で取るときだけ） | 受発注・決済の確定 |
| 中 | 基幹周辺の会議資料・ダッシュボード（汎用BIにしない。一つの会議に付ける） | 在庫・会計のSoR置き換え |
| 低 | 不動産の修繕報告（ビルメンと被るなら急がない） | 査定・与信 |
| しない | 定着支援のデモ、ガバナンス保証のデモ、ERP刷新デモ | — |

新規は ideal と同じく Core接続、体験コードはポータル。Demo Definition はデモ側リポジトリに置く。

## 4. デモ共用のルール

- 体験のURLは1つ。サイト側のリード文だけ変える
- AXEON: 何で動くか、自社データ、既存システムは残る、最終判断は残る、所要と登録
- ideal: 最初の一手、登録不要、1現場から
- 記事の法令・手順をAXEON LPに要約して貼るのは可。図解SVGの複製は、元HTMLを直したらこちらも直す運用が要るので原則リンク

## 5. 実装順

ideal P0（ハブと図）が先。その間にAXEONはA0・A1（テーマと境界のページ）を進めてよい。

- [ ] A0 テーマ5・業界5・境界の表を営業と固定
- [ ] A1 テーマハブ＋industryに境界ブロック＋contact
- [ ] A2 idealの倉庫・運送・シフトURLを業種ページへ
- [ ] A3 ナレッジ導線、必要なら見積下書き（商社が案件化されたら）

やらないこと:

- ideal記事9本をAXEONの見た目で複製する
- ハブに「自動化」「定着支援」を記事タイトルとして並べる（サービスとしてはA1で出す）
- 介護・保育・飲食をAXEON注力5に無理に足す
