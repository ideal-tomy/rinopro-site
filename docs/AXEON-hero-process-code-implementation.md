## コードでの再現方法

### 元画像と同じ基準キャンバス

元画像の実寸をW・Hとして、同じ座標系のキャンバスをコードで組み立てます。

- 元画像の実寸を確認し、比率を推測で決めない。
- 外側は `aspect-ratio: W / H`。
- 内側は元画像と同じW・Hを基準に配置する。
- 列幅、見出し位置、帯の高さ、文字領域を元画像から測る。
- 図全体を同じ倍率で拡大・縮小する。
- 通常のカード一覧として再構成しない。
- 忠実な配置のため、キャンバス内部にabsolute配置を使ってよい。
- ページの他要素へabsolute配置を広げない。

### 文字

- 見出し・本文・箇条書きはHTMLの文字。
- フォント、サイズ、太さ、行間、行数を元図に合わせる。
- この図内では元画像の改行を再現するため、明示的な改行を使ってよい。
- 元図と異なる位置で改行が増える場合、まず文字領域の幅を修正する。
- 小さい文字を大きくして全体の構成を変えない。
- 要約、省略記号、非表示で情報量を減らさない。
- canvasや画像へ文字を焼き込まない。

この図内に限り、通常の本文向けの最小16pxなどの可読性基準を適用しません。図の外側の文章は変更しません。

### 図形・アイコン

- ターゲット、設計図、モニター、ロケット、シールドはSVGで元の形と色に近づける。
- 意味が似ているだけの別アイコンに置き換えない。
- 番号の円、矢印型帯、仕切り、背景図形はCSS・SVGで再現。
- 下部帯の青い光や接続線もCSS・SVGで再現。
- 正式なロゴSVGがある場合は使用してよい。
- 正式ロゴが画像でしか存在しない場合は、そのロゴだけを利用してよい。利用箇所を報告する。
- 図全体・各列を画像で貼る方法は禁止。
- SVGのimage要素にスライド全体を埋め込む方法は禁止。
- 元画像を完成版の背景に残して、再現できたことにする方法は禁止。

## PC・スマホ

**全画面幅で、5列・上部見出し・下部ブランド帯の位置関係を維持します。**

- Hero内の図の表示位置・表示幅は、画像を使っていた時の配置を基準にする。
- スマホでは図全体を縮小する。
- 各列の縦積み、横スライド、タブ、詳細開閉は追加しない。
- 左右ボタン、ページ番号、新しい補足文章も追加しない。
- 図全体の縦横比を変えない。
- 文字だけを別倍率で大きくしない。
- 内部構成をブレークポイントで変更しない。
- ページ全体の横はみ出しを防ぐ。

scaleを使う場合、外側の要素には**縮小後の高さ**を確保してください。transformだけを掛けて、元の高さの空白を残してはいけません。

サイズ計測が必要ならResizeObserverを使用してよいですが、表示幅と基準W・Hから倍率を決めます。内容の高さを計測して倍率が循環的に変わる実装は避けてください。

図の上下の切れ、読み込み時の大きな移動、不要な空白を確認してください。

2. 上部見出し、列の境界、帯、番号、アイコン、段落、下部帯を順に比較する。
3. 位置・大きさ・配色・改行の相違を修正する。
4. 比較用画面でのみ元画像を半透明で重ねて、ずれを確認してよい。完成版には残さない。
5. 両ページの強調状態を確認する。
6. PC・スマホで図全体の比率が保たれることを確認する。
