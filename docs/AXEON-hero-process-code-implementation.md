# AXEON｜Heroの5工程図をHTML/CSS・SVGへ置き換える実装指示書

## 目的と対象

コンサルティングページと半内製化ページのHero右側にある、5工程のスライド画像を、Webサイトのフォント・配色・余白に合わせたコードの図解へ置き換えてください。

現在は `services01.jpg` などのスライド画像に、支援対象を示す赤・オレンジの枠と色を重ねています。これを廃止し、工程そのものの背景色と文字色で対象範囲を示します。

対象は以下です。

- コンサルティングページ：Hero右側の図
- 半内製化ページ：Hero右側の図
- 必要な共通コンポーネント、SVG、スタイル

Hero左側の文章、ヘッダー、CTA、ページ内導線、他セクションは、現在の実装を維持してください。以前のスクリーンショットにある削除済みの文章や契約条件を復活させないでください。

## 参照画像

この指示書と一緒に、次のスクリーンショットを実装担当のCodexへ渡してください。

- `スクリーンショット 2026-10-12 223427.png`：コンサルティング
- `スクリーンショット 2026-10-12 223419.png`：半内製化

参照するのは、右側の図の「工程の内容と順序」です。スライドの装飾、ロゴ帯、細かな文字サイズ、赤い囲みをそのまま再現する依頼ではありません。

実装前にリポジトリ内の元画像と、その画像を使用しているコンポーネントを確認してください。添付だけでは細かな説明が読み取れない場合、元画像を確認し、不明な文字を推測で補完しないでください。

## 完成形の構成

右側は、次の構成にします。

1. 短い全体説明
2. 左から右につながる5工程
3. このページで主に説明する範囲の文字表示
4. 必要な人が開ける「各工程の詳細」

短い全体説明：**戦略の整理から開発・運用まで**

工程は必ず次の順番です。

| 工程 | 表示名 | Hero内に表示する短い説明 | SVG |
|---|---|---|---|
| 1 | 戦略コンサルティング | 目標と取り組む順番を整理 | ターゲット |
| 2 | ITコンサルティング | 業務とシステムの方針を整理 | 設計図・業務フロー |
| 3 | システム開発 | 必要な仕組みを設計・開発 | コードを表示するモニター |
| 4 | 導入・展開 | 現場で使える状態にする | ロケット |
| 5 | 運用・保守 | 運用を支え、改善を続ける | シールド |

この短い説明は、元画像の内容をHero向けに要約した文です。元画像の細かな説明は削除せず、後述の詳細欄で扱います。

5工程を3工程にまとめないでください。支援範囲だけを取り出して、残りを消してはいけません。

## 共通化とページごとの差分

5工程のデータと表示コンポーネントは共通化し、ページごとに強調する工程だけを変更します。

| ページ | 強調する工程 | 図の下に表示する文字 |
|---|---|---|
| コンサルティング | 1・2 | このページで主に説明する範囲：戦略・ITコンサルティング |
| 半内製化 | 3・4・5 | このページで主に説明する範囲：開発・導入・運用 |

**半内製化でも1・2を表示します。** 半内製化は課題整理・コンサルティングを含むため、1・2を支援対象外と誤解させないでください。

「対象外」「対応しない」「開発のみ」などの表現は禁止です。色の違いはページ内での説明の中心を示すものです。

実装例としては、工程データと `highlightedStageIds` を共通コンポーネントへ渡す形が適しています。既存の構造に合う名前を使って構いません。

## PCのデザイン

### Hero内の位置

- 左側は現在のHeroテキスト。
- 右側は新しい工程図。
- 共通コンテナの幅と左右の余白を継承する。
- 右側に図全体を囲む追加のカード・枠・影を設置しない。
- 図の下にスライド風のロゴ帯を置かない。
- 図の背景は、Hero背景となじむ淡い青灰色を基本とする。
- 図のためだけに右側のpaddingや独立した小さなmax-widthを増やさない。

右側の表示幅は640px以上を目安にしてください。5列を保つことで文字が読みにくくなる幅では、図を縮小せず、後述の横スクロール表示へ切り替えます。

### 図そのもの

5つの工程を、連続した一つの流れとして見せます。

- 等幅5列。
- 工程間の間隔は8pxを基準。
- 工程の上部に「番号＋工程名」。
- 番号は工程名の左側に、小さく同じ行で配置する。
- その下にSVG、その下に短い説明。
- 工程名の領域の高さを揃え、長い工程名は自然に2行まで使えるようにする。
- 番号を独立した大きな見出しにしない。
- 番号自体を途中で折り返さない。
- 各工程の文字はHTMLで表示する。

工程間は、小さな右向きの接続記号でつなぎます。接続記号は工程の順序を表すもので、装飾的な縁取りではありません。

上部の工程名の面を、右端が矢印になる形にしても構いません。ただし、文字はclip-pathの対象にせず、背景だけを図形化してください。文字の末尾が矢印部分と重ならないようにします。

### レイアウトの基準値

| 要素 | 基準 |
|---|---|
| 図全体の説明 | 18px、700、行高1.5 |
| 全体説明→工程図 | 20px |
| 工程名 | 14px、700、行高1.5 |
| 工程番号 | 12px、700 |
| 工程名領域 | 最小高さ48px。文字拡大時は伸びる |
| SVG領域 | 高さ72〜88px |
| SVG実寸 | 48〜60px |
| 短い説明 | 14px、400、行高1.65 |
| 工程内の左右余白 | 10〜12px |
| 工程内の上下余白 | 16px |
| 角丸 | 最大6px |
| 工程図→範囲の説明 | 16px |
| 範囲の説明 | 14px、行高1.7 |
| 詳細を開く操作 | 14〜16px |

Heroの右側に置く図のため、工程名や一文を14pxとしています。詳細欄の本文は16pxを使います。狭くなったことを理由に、さらに文字を小さくしないでください。

高さは内容で決めます。固定高さで文字を隠す、説明を省略記号にする方法は禁止です。

## 色による支援範囲の表示

### 通常工程

- 工程名の面：#E7EFF7
- 工程名の文字：#183654
- 工程本文の面：#F5F8FC
- 説明文：#24364B
- SVG：#567A9Eを主色にする

### 強調工程

- 工程名の面：#123D6B
- 工程名の文字：#FFFFFF
- 工程本文の面：#E0EDF9
- 説明文：#0B2443
- SVG：#246FC4を主色にする
- 必要な小さな補助色のみ：#E98532

**強調は面全体の色で行い、赤い枠をかぶせません。**

通常工程も十分に読めるコントラストを保ちます。opacityで図全体を薄くして読めなくする方法は禁止です。

色だけで区別せず、図の下の文字でも、このページで主に説明する範囲を明記してください。

## SVGの条件

5種類のSVGを、同じ線幅・大きさ・青系の配色で作ります。

- 原画像の意味を維持する。
- 線幅は2〜2.5px相当を基準に揃える。
- 線と淡い面を組み合わせる。
- 黒一色のアイコンや絵文字は使わない。
- 外部画像URLへ依存しない。
- 図全体をSVG画像にして文字まで焼き込まない。
- ラスター画像をSVGの中に埋め込む方法は禁止。
- 無意味なアニメーション、発光、3D加工は追加しない。
- SVGを使うためだけに、新しいライブラリを追加しない。
- 既存のアイコン資産が適していれば利用してよいが、見た目の統一を確認する。

モニターの中のコード記号などはSVGの図形で表現して構いません。工程名・説明文・詳細は通常のHTML文字として残します。

## 元画像の細かな内容を残す詳細欄

Hero内に、元画像の全項目を極小文字で詰め込まないでください。

図の下に「各工程の詳細」という開閉操作を設け、開いたときに元画像の細かな説明をHTMLで表示します。

- 初期状態は閉じる。
- 開くと、Heroの右側の領域内で下へ自然に展開する。
- ポップアップやモーダルにしない。
- 詳細領域内だけの縦スクロールを設けない。
- 各工程の見出しに続けて「何をするか」「なぜ必要か」「確認する情報」を整理する。
- 元画像の見出しが「お客様から必要な情報」なら、項目の意味を保った上で「確認する情報」に統一してよい。
- 原画像の項目は元画像や元データを確認して転記する。
- スクリーンショットで不鮮明な項目を、想像で追加しない。
- 不明な項目は実装報告に記載し、架空の項目で埋めない。
- 詳細の見出しは16〜18px、本文は16px・行高1.75。
- 詳細は工程ごとに縦並び。さらに5列の小さな箱へ詰め込まない。

共通コンポーネントでは、短い説明と元画像の詳細データを分けて管理してください。

## スマホ・中間幅

### Hero全体

既存のスマホHeroの構成に合わせて、テキストの下に図を配置します。PCの配置を画像のように一括縮小しません。

### 工程図

- 工程を一つずつ読める横スクロール表示。
- スマホの工程幅は表示領域の約82〜86%。
- 右側に次の工程が少し見える。
- 工程間隔は12px。
- 工程名18px、短い説明16px。
- SVGは72pxを基準。
- scroll-snapを使用。
- 自動再生、自動反転はしない。
- 工程の高さは行内で揃えるが、文字を切らない。
- ページ全体の横はみ出しは起こさない。
- 左右ボタンと「1 / 5」の現在位置表示を図の外側に配置する。
- 現在位置はタッチ操作、ボタン操作、手動スクロールに同期する。
- 先頭・末尾では移動できない方向のボタンを無効化する。
- キーボード操作でも移動できるようにする。

1工程しか大きく見えない場合も、必ず番号と「1 / 5」で全5工程の一部だとわかるようにします。

中間幅でも、工程の外幅が約120px未満になる場合は、5列を無理に維持しません。横スクロールに切り替え、工程幅180〜220px程度を確保します。

PC5列とスマホ横スクロールは同じ工程データから描画します。詳細もページごとにコピーして二重管理しません。

## 枠・文字・余白の禁止事項

- 左辺だけの青線・赤線・オレンジ線を付けない。
- 上辺・下辺だけの強調線、角だけの縁取りを付けない。
- 図全体に追加の装飾枠を付けない。
- 原画像の上にabsolute配置の長方形を重ねる方法を残さない。
- 色付き枠で強調する方法へ戻さない。
- スライド上部の会社名や、下部のAXEONロゴ帯を復活させない。
- 文字の幅に独立した65ch・70%などの制限を設けない。
- 右側だけ意味のないpaddingを足さない。
- 文中の不自然な位置にbrを挿入しない。
- 日本語本文へword-break: break-allを一律適用しない。
- 極小文字で情報量を維持しない。
- 図の置き換えに合わせて、対象外の本文やセクション構成を変更しない。

## スクロール演出と安定性

既存の演出を確認し、この図に親子で重複した表示アニメーションを掛けないでください。

- 図全体を表示する演出は最大1回。
- 横スクロール中に工程の上下位置が変わらない。
- 工程が画面内に入るたびにtranslateYを再実行しない。
- 図解、見出し、本文へ別々の遅延アニメーションを追加しない。
- マウント時やフォント読み込み時に工程の高さが大きく変化しないようにする。
- SVGの領域は読み込み前から確保する。
- reduced-motionでは表示演出と滑らかな移動を抑える。
- 既存ページ全体の演出には、必要な範囲以外の変更を加えない。

## 実装の手順

1. 両ページのHeroと画像・重ね枠の実装を確認する。
2. 原画像に書かれた詳細を確認する。
3. 5工程の共通データとコンポーネントを作る。
4. HTMLの工程名・説明とSVGを組み合わせる。
5. ページごとの強調範囲を設定する。
6. 詳細欄と狭い画面の横スクロールを実装する。
7. 旧画像と重ね枠をHeroから外す。
8. 両ページの実際の表示を確認して、文字と余白を調整する。
9. 変更箇所、確認結果、読めなかった元画像の項目があれば報告する。

元画像ファイルは、他のページで使用している可能性があるため削除しません。対象Heroから参照を外すだけにしてください。

Next.js／TypeScript／Tailwind等、リポジトリの既存構成に合わせます。新しいUIライブラリを導入しません。
