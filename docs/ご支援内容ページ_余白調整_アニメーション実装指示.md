# ご支援内容ページ｜横幅・余白調整＋アニメーション実装指示

対象:
- 「ご支援内容」ページ
- 添付スクリーンショットの現行デザイン

目的:
- 現在のデザイン・掲載内容は変更しない
- セクションごとの横幅と左右余白を調整し、画面をより有効に使う
- 特に「コンサルティング / 半内製化」の2カードを、他セクションより広く見せる
- スクロール時の自然なアニメーションを追加する
- PC / SPともに、現在の構成を崩さず見栄えを改善する

---

# 0. 最重要ルール

今回の修正では、以下を変更しないでください。

- 掲載内容
- テキスト
- 見出し
- 画像
- アイコン
- 配色
- カードの基本デザイン
- セクションの並び順
- CTA文言
- ナビゲーション内容

今回変更するのは、主に以下です。

1. セクションごとの最大横幅
2. 左右余白
3. カードの表示幅
4. セクション進入時のアニメーション
5. カードや要素の表示順
6. PC / SPでの自然なレスポンシブ調整

「デザイン変更」ではなく、
現在のデザインを活かしたまま、
画面の使い方と見せ方を改善する作業です。

---

# 1. ページ全体の横幅方針

現在は、全セクションがほぼ同じ横幅・同じ左右余白で表示されており、
特にPCでは中央に小さくまとまって見えます。

セクションごとに役割が違うため、
全て同じ `max-width` に固定しないでください。

基準:

```css
--content-narrow: 1120px;
--content-default: 1240px;
--content-wide: 1360px;
```

目安なので、既存レイアウトとの整合を見て微調整して構いません。

重要なのは、

- すべて同じ横幅にしない
- 「コンサルティング / 半内製化」は最も広くする
- 下の4カードはそれより少し狭くてもよい
- PROCESSは読みやすい幅を維持する

という階層です。

---

# 2. Heroセクション

Heroは現在の見た目を維持。

横幅は `default` 程度。

```css
max-width: 1240px;
```

左右余白:

```css
padding-inline: 32px;
```

程度。

1920pxなどの大画面で、
中央に小さくなりすぎないこと。

---

# 3. 「コンサルティング / 半内製化」カード

ここは今回の最重要調整箇所です。

現在より左右余白を減らし、
他セクションより横幅を広く表示してください。

## PC

この2カードを包むcontainerは、

```css
max-width: 1360px;
```

程度。

左右paddingは、

```css
padding-inline: 24px;
```

程度まで減らしてよい。

画面幅が十分ある場合は、
ページ内で最も広く見えるセクションにしてください。

---

# 4. 2カードの横幅配分

「コンサルティング」
「半内製化」

は同じ幅。

```css
grid-template-columns: repeat(2, minmax(0, 1fr));
gap: 24px;
```

程度。

現在より各カードの横幅を大きく見せる。

カード内部の、

- テキスト
- 画像
- ボタン

の位置関係は変更しない。

画像を大きくする目的ではなく、
カード全体の面積と余白を増やし、
主役セクションとして見せる。

---

# 5. 他セクションとの差

「コンサルティング / 半内製化」は `wide`。

SERVICE MENUは `default`。

PROCESSは `narrow〜default`。

全セクションを同じwidthにしない。

---

# 6. SERVICE MENU 4カード

「目的に合わせて、必要な支援を選べます。」

の4カードは、
現在のデザインを維持。

横幅は `default` 程度。

```css
max-width: 1240px;
```

4カードが広がりすぎないようにする。

主役は上の2カードなので、
こちらは整理された一覧として見せる。

---

# 7. PROCESSセクション

「課題の整理から運用まで、一気通貫でサポートします。」

は現在の横並び工程を維持。

PCでは、

```css
max-width: 1180px;
```

程度でもよい。

PROCESSは横幅を最大化するより、
各ステップ間の流れが読みやすいことを優先する。

---

# 8. セクション左右余白

PC:

```css
padding-inline: clamp(20px, 3vw, 48px);
```

を基本。

ただし、

「コンサルティング / 半内製化」

だけは広く見せるため、
最大左右余白を他より少なめにする。

例:

```css
padding-inline: clamp(16px, 2vw, 32px);
```

---

# 9. Tablet

768〜1024pxでは、
無理にPC幅を維持しない。

「コンサルティング / 半内製化」は
2列維持できる幅なら2列。

狭い場合は1列へ切り替える。

カードが細長くなりすぎるより、
1列表示を優先。

---

# 10. Mobile

SPでは左右余白を、

```css
padding-inline: 16px;
```

程度。

「コンサルティング / 半内製化」は1列。

各カードは、

```css
width: 100%;
```

。

PCの「広く見せる」は、
SPでは「画面幅を十分使う」に置き換える。

SPで横スクロールは発生させない。

---

# 11. アニメーション方針

今回のアニメーションは、
現在の落ち着いたBtoBデザインを壊さないこと。

派手な動きは禁止。

使用するのは、

- fade
- slight translate
- stagger
- subtle scale

のみ。

---

# 12. Heroアニメーション

Heroセクションがviewportに入った時、

1. 見出し
2. 説明文
3. 右画像

の順番で表示。

## 見出し

```css
opacity: 0 -> 1
translateY(12px) -> 0
duration: 500ms
```

## 説明文

80〜100ms遅れ。

## 右画像

さらに100〜150ms遅れ。

```css
opacity: 0 -> 1
translateX(14px) -> 0
duration: 550ms
```

---

# 13. コンサルティング / 半内製化カードのアニメーション

この2カードは、
ページ内の主役として少し丁寧に表示する。

## 表示順

1. コンサルティング
2. 半内製化

完全同時表示にしない。

## コンサルティング

```css
opacity: 0 -> 1
translateY(16px) -> 0
duration: 550ms
```

## 半内製化

約100〜140ms遅れて表示。

```css
opacity: 0 -> 1
translateY(16px) -> 0
duration: 550ms
```

---

# 14. カード内部の表示

カード内部の要素まで細かくバラバラに出しすぎない。

ただし、

- タイトル
- 箇条書き
- CTA

については軽いstaggerを入れてもよい。

例:

title
↓ 60ms
body / list
↓ 60ms
button

画像はカード本体と同時でよい。

---

# 15. hover

PCのみ。

コンサルティング / 半内製化カードに、

```css
transform: translateY(-3px);
```

程度。

shadowを少しだけ強くする。

duration:

```css
180〜220ms
```

大きく浮かせない。

画像をズームさせない。

---

# 16. SERVICE MENUアニメーション

4カードは左から順番表示。

```text
card1
↓ 70ms
card2
↓ 70ms
card3
↓ 70ms
card4
```

各カード:

```css
opacity: 0 -> 1
translateY(12px) -> 0
duration: 450〜500ms
```

PCでのみstaggerを明確にする。

SPでは、
表示が遅すぎないようstaggerを40〜60ms程度に短縮。

---

# 17. PROCESSアニメーション

PROCESSは、
「流れ」を感じられる表示にする。

表示順:

1. 見出し
2. ステップ1
3. ステップ2
4. ステップ3
5. ステップ4
6. ステップ5
7. 下部CTA

各ステップは、

```css
opacity: 0 -> 1
translateY(8px) -> 0
```

程度。

80ms前後ずつstagger。

---

# 18. PROCESS接続線

既存の横線がある場合、
レイアウト自体は変更しない。

可能であれば、
線だけ少し遅れて表示。

複雑なline drawing animationは不要。

単純なopacity transitionで十分。

---

# 19. 下部CTA

PROCESS最後のCTAは、
全工程の表示後に少し遅れて表示。

```css
opacity: 0 -> 1
translateY(8px) -> 0
duration: 400ms
```

---

# 20. スクロールアニメーションの発火

各セクションは、
viewportへ30〜40%程度入った時点で表示開始。

一度表示したら、
スクロールで画面外へ出ても再び非表示にしない。

再進入するたびにアニメーションを繰り返さない。

---

# 21. 実装方法

新しいライブラリを追加しない。

既存でFramer Motion等が導入済みなら使用可。

未導入の場合は、

- CSS transition
- IntersectionObserver

で実装する。

今回のためだけに
animation libraryをinstallしない。

---

# 22. prefers-reduced-motion

必ず対応。

```css
@media (prefers-reduced-motion: reduce)
```

では、

- translate
- scale
- stagger

を停止。

即時表示またはopacityのみ。

---

# 23. アニメーション速度

基本:

```text
400〜600ms
```

カード間stagger:

```text
60〜140ms
```

hover:

```text
180〜220ms
```

1秒を超える演出は原則使わない。

---

# 24. 禁止事項

今回、以下は変更しない。

- 現在のデザインテーマ
- 現在のカードデザイン
- 配色
- テキスト
- 画像
- セクション順
- CTA文言
- ナビゲーション

以下も禁止。

- 新しい装飾カード追加
- グラスモーフィズム
- neon glow
- bounce
- rotation
- perpetual animation
- parallax
- 背景動画
- 画像zoom hover
- アニメーションのためだけのライブラリ追加

---

# 25. 実装前に確認すること

コード変更前に、

1. 各セクションのcontainer
2. 現在のmax-width
3. padding-inline
4. card grid
5. responsive breakpoint
6. 既存animation library
7. CSS / Tailwind設定

を確認する。

現在の共通containerをそのまま全セクションに使っている場合は、
セクションごとにwidth variantを作る。

例:

```text
container--wide
container--default
container--narrow
```

---

# 26. 推奨container設計

例:

```css
.container-default {
  width: min(100% - 48px, 1240px);
  margin-inline: auto;
}

.container-wide {
  width: min(100% - 32px, 1360px);
  margin-inline: auto;
}

.container-narrow {
  width: min(100% - 48px, 1120px);
  margin-inline: auto;
}
```

実プロジェクトのCSS設計に合わせて実装する。

固定値をそのままコピーする必要はない。

- 「コンサルティング / 半内製化」が他セクションより広く見える

# 最終意図

今回の修正では、
デザインそのものを変えない。

現在のデザインを活かしたまま、

- 横幅
- 左右余白
- セクションごとの強弱
- 表示される順番

だけを改善する。

特に、

「コンサルティング / 半内製化」

をページ内の主役として、
他セクションより横幅を広く使用する。

その下のSERVICE MENUとPROCESSは、
情報整理のために少し落ち着いた幅を維持する。

アニメーションは、
装飾ではなく、
ユーザーの視線を上から下へ自然に誘導するために使用する。
