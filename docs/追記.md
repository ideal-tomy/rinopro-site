| 追記すること | 理由 |
|---|---|
| **ロゴ・「戻る」・ヘッダー・フッターのリンク先も確認する** | 問い合わせ先だけ直しても、別の出口からIDEALへ戻る可能性があるため |
| **見積もりの保存・復元でブランドが上書きされないことを確認する** | URLが正しくても、保存データの復元処理で変わらないか確認が必要 |
| **本番の見積もりCTAは「非表示なら合格」にしない** | 環境変数未設定時の非表示は互換仕様として妥当ですが、必要な導線が消えたままでは今回の目的を満たさないため |
| **製造デモの紹介文変更は、リンク修正と分けて扱う** | 「ナレッジ回答の紹介を、品質不具合対応の紹介へ変える」は、技術修正に加えて掲載内容の選択になるため |

もう一点、**この計画は「別ドメインへ移動しなくする計画」ではなく、「別ドメインの共通デモでもAXEONとしてつなぐ計画」**です。

AXEONから開いても、アドレスは引き続きconstruction-demo-six.vercel.appなどになります。表示ブランドと問い合わせ先がAXEONになればよい、という目的なら、この方式で合っています。

Codexには、次を追加すればよいと思います。

既存PLANに以下を追記して実装してください。

1. 問い合わせ・見積もりだけでなく、ロゴ、ヘッダー、
   フッター、「サイトに戻る」、完了画面の全外部リンクを確認する。
   存在する戻り導線も、解決済みブランドに対応させる。

2. 見積もりの保存・復元処理で、URLから解決したブランドが
   別ブランドの保存データに上書きされないことを確認する。

3. 本番で必要な見積もりCTAが非表示の場合は、
   「ブランドの誤誘導なし」として完了にせず、未解決として報告する。

4. 製造デモの紹介内容変更は、ブランド導線修正と分けて提示する。
   リンク先を維持するか、紹介に合うデモへ変更するかを
   技術上の都合だけで決めない。

5. 公開後は実際のAXEON・IDEALの入口から操作し、
   表示ブランドと、各出口の実際のURLを確認して完了とする。
