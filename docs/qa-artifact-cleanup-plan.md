# QA生成物の整理計画

更新日: 2026-10-10

## 目的

ブラウザー確認のたびに `docs/` 配下へ蓄積したスクリーンショットと計測JSONを整理し、サイト実装に使う素材と確認用の出力を分ける。アプリの表示・動作と、ユーザーが渡した仕様書やデザイン資料は変更しない。

## 分類と扱い

1. `public/` 内の画像・フォント等は、実装からの参照が見つかったものを含めサイト素材として保持する。
2. `docs/` 直下のモックアップ、スクリーンショット、実装仕様書、調査資料は入力・設計資料として保持する。
3. 日付付きQAフォルダー内のPNG/JPG/WebP/JSONは、`docs/`、`src/`、`scripts/` のテキストファイルからファイル名で参照されるものを保持する。参照が見つからず、サイトの実行時素材でもない生成物のみ削除する。
4. レポート、README、検証スクリプト、比較用HTML、コードのbeforeスナップショットなどは保持する。これらの確認手順・説明を残し、参照先を壊さない。
5. 空の一時ファイル `docs/_demo-export-temp.json` と空ディレクトリ `docs/files/` は、用途と内容がなく、サイト参照もないことを確認できた場合に限り削除する。

## 実施と確認

- 削除候補の絶対パスが対象QAフォルダー内に収まることを検査してからファイル単位で削除する。フォルダー再帰削除は行わない。
- 削除数・容量を記録し、残ったREADME/レポート内の画像・JSONリンクが存在することを検査する。
- `public/` とソースコードは変更せず、ビルドとQA用ページの疎通を確認する。
- 今後のQA出力は一時作業領域へ出し、納品・比較に必要な結果だけを `docs/` に残す。

## 実施結果

- `docs/`、`src/`、`scripts/` のテキストから参照されないQA出力を151ファイル削除（PNG等105点、JSON 46点、計43,378,810 bytes / 約41.37 MiB）。
- 内容が空の `docs/_demo-export-temp.json` と、ファイルのない `docs/files/` も削除。
- README、検証レポート、スクリプト、比較HTML、参照のあるQA画像・JSON、サイトコード、`public/` の素材、ユーザー提供資料は保持。
- 削除後、半内製化・コンサルティング・進め方ページはいずれもHTTP 200を返すことを確認。ビルドはこの整理より前に成功しており、アプリコードとサイト素材には変更を加えていない。
