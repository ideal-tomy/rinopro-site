# AXEON コンサルティングページ実装指示書 v3

## 依頼

既存の `/services/consulting` を、同時に添付する完成イメージに忠実に改修してください。企画し直す依頼ではありません。承認済みの構成・図解・配色・文字の強弱・余白を、実際に読めるWebページとして再現してください。

この指示書は、以前のコンサルティングページ実装指示書より優先します。今回削除するセクションを、以前の指示に従って復活させないでください。

完成イメージは、AXEONのヘッダーからフッターまでが入った縦長の画像です。「相談例」の下に、青からオレンジにつながる4項目の「支援内容」図があります。PC/SPを並べた参考画像は、ステップ図の形状参考であり、今回の完成デザインではありません。

## 1. 実装範囲・進め方

- まず既存のページ、共通レイアウト、フォント、スタイル、画像、問い合わせリンクを確認してください。
- 既存プロジェクトのフレームワーク・コンポーネント・アイコンライブラリを使って実装してください。
- 対象はコンサルティングページと、それに必要な局所的なコンポーネント・スタイルです。
- 他ページの構成を変更しないでください。共通CSSへの変更による他ページの表示崩れを避けてください。
- トップとご支援内容ページのブランド・ヘッダー・フッターを引き継いでください。
- 画像全体を1枚の背景として貼る実装は不可です。文章・タブ・ボタンはHTMLで実装してください。
- 新しいパッケージの追加を前提にしないでください。図解・接続線はCSS、SVG、既存アイコンで制作できます。
- 実装、ビルド、PC/SPの表示確認まで進めてください。本番への公開は今回の依頼に含みません。

## 2. 最終構成

以下の順序に固定します。

1. 既存の共通ヘッダー
2. ヒーロー
3. ページ内リンク：支援範囲／相談例／支援内容
4. 支援範囲：図解のみ
5. 相談例：3つのタブ
6. 支援内容：横幅を使った4項目のステップ図
7. ご相談について：問い合わせ導線
8. 既存の共通フッター

削除するもの：

- 「支援範囲」の図解の外にある説明文・補足文・左右2列の文章エリア
- 「資料の見本」セクションと、その拡大表示機能
- 「支援体制」セクション
- 「ご相談から契約まで」セクション
- 削除したセクションへのページ内リンク
- 「支援内容・成果物」のアコーディオン。今回のステップ図に置き換える

「支援内容・成果物」という見出しは残さず、「支援内容」に変更してください。

## 3. 完成イメージを再現する共通ルール

### 横幅・余白

- 完成イメージのように、コンテンツがページ幅の約88〜90%を使う構成にします。
- PCは通常コンテナを `width: calc(100% - 96px); max-width: 1280px; margin-inline: auto` を初期値とします。
- 支援内容の図は通常コンテナより少し広く、`width: calc(100% - 64px); max-width: 1320px` を初期値とします。見出しは通常コンテナにそろえます。
- SPは左右20px、320px幅では16pxを基本にします。
- コンテナ内にさらに理由のない狭い `max-width` を重ねないでください。
- 支援範囲は図解自体が横幅を使います。図の左側に文章を置くための空間を残さないでください。
- 各セクションの上下余白はPC56〜72px、SP36〜44pxを初期値にします。
- 数値は完成イメージから読み取った実装目安です。画像と実ブラウザを比較して調整し、余白の印象・各要素の比率を合わせてください。
- セクションの固定高さで無理に画像に合わせないでください。自然な文章量と余白で整えます。

### 色

| 用途 | 初期値 |
| --- | --- |
| ページ背景 | `#FFFFFF` |
| ヒーロー・相談例の淡い背景 | `#F0F8FF` |
| 見出し・濃紺エリア | `#0B1933` |
| 本文 | `#111111` |
| ブランドブルー・図解線 | `#234B9D` |
| 青いアイコンの基調 | `#0758C4` |
| 淡い区切り線 | `#D5E2F2` |
| 最終ステップのアクセント | `#FFA51F` |
| 最終ステップの淡い背景 | `#FFF5E3` |

実際の既存ブランド色が確定している場合は、それを優先しつつ、完成イメージの青・紺・淡青・オレンジの関係を再現してください。本文を薄いグレーにしないでください。

### 文字

- 日本語フォントは既存サイトと統一します。既存に指定がない場合はNoto Sans JP等の読みやすいゴシック体を使用します。
- PCのH1は48〜56px、SPは32〜36pxを初期値とします。
- H2はPC36〜40px、SP28〜30px。全セクションで同じ階層にそろえます。
- 本文はPC16〜18px、SP16px。行間は1.7〜1.8。
- ステップ内の説明も原則16px以上。文字を小さくして4項目を押し込まないでください。
- 見出しの太さは700〜800、本文は400〜500。強調箇所だけを太くします。
- 完成イメージの短い青い下線を「相談例」「支援内容」に付けます。幅40〜48px、高さ3px、見出しとの間隔10〜12px。
- 小さいセクション名の下に大きい抽象的なコピーを重ねる構成は使いません。
- 本文の改行は基本的に幅による自然な折り返しに任せます。`word-break: normal; overflow-wrap: break-word` を基本にしてください。
- 段落を細切れにする大量の `<br>`、文字単位の装飾span、狭い固定幅による不自然な折り返しは不可です。
- 完成画像のH1にあるような、最後の「グ」だけが次行に落ちる改行は再現しないでください。画像の生成上の文字崩れは修正します。
- タイトルが収まらない場合は、カラム幅・文字サイズを調整するか、意味のまとまりで折り返してください。

### 装飾

- 全体は企業Webサイトとして、白・淡青・紺を中心に落ち着いて仕上げます。
- 影は原則なし、使う場合も弱くします。角丸は0〜6px程度。
- 全部をカードにしないでください。支援範囲の関係図、相談例のタブパネル、支援内容の連続図、それぞれの構造を使い分けます。
- 不要な01・02などの番号、大きい英語飾り見出し、背景の装飾図形、白いカプセルタグの大量使用は追加しません。
- 色の異なる4つの独立カードではなく、つながった図として支援内容を表現します。

## 4. ヒーロー

### 配置

- 淡い青の背景をページ幅いっぱいに広げます。
- PCは左にタイトル・説明、右に既存画像。左右比率は約44:56、間隔32〜48px。
- 左右の内容を縦方向の中央にそろえます。
- H1、太い説明、通常の説明の順に強弱を付けます。
- 画像に追加の背景カード・外枠・影を付けないでください。

### 掲載文

H1：

> コンサルティング

太い説明：

> 業務やシステムの見直しを、計画づくりから支援します。

通常の説明：

> 経営の方針と現場の状況を確認し、取り組む範囲と進め方をまとめます。

H1との間は24〜32px、説明同士の間は18〜24pxを初期値にします。説明の右側に過剰な空白を残さないでください。

### 右側画像：必須条件

- 現在使っている `services01.jpg` を使います。
- その画像上の①戦略コンサルティング、②ITコンサルティングを囲う2つのオレンジ枠を含め、現在の表示を再現してください。
- ③システム開発、④導入・展開、⑤運用・保守、および下部の紺色AXEON帯もすべて残します。
- 2つの強調枠を、画像全体を囲う1つの枠に置き換えないでください。
- すでに画像に枠が焼き込まれている場合は、さらに枠を追加しないでください。
- 枠がHTML/CSSの重ね合わせで作られている場合は、その実装と画像基準の位置・幅・高さを引き継ぎます。SPでも画像に追従するよう比率で配置してください。
- 比率を維持し、`object-fit: contain`。画像の一部を切り抜いたり、別のイラストに差し替えたりしません。

SPではタイトル・説明・画像の順に縦に並べます。画像は横幅いっぱいを使い、枠がずれないよう確認します。

## 5. ページ内リンク

- ヒーロー直後に白背景の細いナビゲーションを置きます。
- 「支援範囲」「相談例」「支援内容」の3項目だけを表示します。
- 左寄せ、間隔28〜40px。下に淡い青の細い区切り線。
- 完成イメージと同様に、支援範囲のリンクに初期の青い下線を付けます。現在位置追従を実装する場合は実際の表示位置と一致させてください。
- 削除したセクションへのリンクを残さないでください。
- 各対象にIDを付け、ヘッダー分の `scroll-margin-top` を設定します。

## 6. 支援範囲：図解だけで伝える

### 表示する内容

図解の外には、見出し・説明文・脚注・キャッチコピーを表示しません。アクセシビリティ上のセクション見出し「支援範囲」は、視覚的に非表示のH2として残せます。

図の関係は以下のとおりです。

| 位置 | 主文 | 補足・項目 |
| --- | --- | --- |
| 左上 | 経営の方針 | 目標・投資・優先順位 |
| 左下 | 現場の状況 | 業務・情報・既存システム |
| 中央 | AXEON | 課題と対応方法を整理 |
| 右 | 社内で検討するための計画 | 変更する範囲／着手する順番／担当と進め方 |

### PCの形状

- 左の2つの入力ブロックから線を合流させ、中央のAXEONブロックに矢印でつなぎます。
- 中央から右の計画ブロックへ、もう1本の矢印を伸ばします。
- 左は淡青、中央は白地に青い細枠、右は濃紺に白文字。
- 左はビル・人、中央は資料と虫眼鏡、右は書類のシンプルな線画アイコン。
- 右の3項目には小さなチェックマークを付けます。
- ブロックの横幅は左約30%、中央約25%、右約30%を目安にし、残りを接続線と間隔に使います。
- 接続線は2〜3px。アイコンと文字の色をそろえます。
- 右側の計画を最も強く見せます。全ブロックを同じ背景・同じ大きさのカードにしないでください。
- 説明エリアを削除した分、図解を中央に広げます。

### 実装方法

見た目は1つの図解ですが、文字はHTMLとして保持し、線やアイコンをSVG/CSSで描く実装を優先します。これによりSPでも文字が読めます。SVG内テキストで制作する場合も、縮小によって文字が読めなくならないようにしてください。

SPでは入力2項目を上段、AXEONを中段、計画を下段に配置し、接続方向を下向きに変えます。図全体の単純縮小は不可です。入力2項目が横に収まらない幅では縦に並べて構いません。

## 7. 相談例：現状の内容を活かし、文字の強弱を付ける

### 外観

- セクション全体は淡い青背景。
- H2「相談例」と短い青い下線を表示します。長い導入説明は追加しません。
- タブ3つ、その下に白いパネル1つを置きます。
- 選択タブは白地・青い太文字・下端の青い線。非選択タブは少し濃い淡青背景。
- パネルの外枠は淡青の1px。二重枠にしないでください。
- PCは左約40%、右約60%。左に相談状況、右に確認・比較・まとめる内容。
- 左右の間に淡い青の細い縦線。パネル内余白は28〜36px。
- 左の小見出し「相談の状況」は青、相談タイトルはPC24〜28px・太字、本文は通常の大きさ。
- 右の「確認すること」「比較する対応方法」は青い太字。項目間に20〜24pxの間隔。
- 「まとめる内容」は淡青の背景で囲み、結論をPC20〜22px・太字で表示します。
- 太字や青文字を本文全体に適用せず、見出しと結論に集中させます。

### タブと文言

既存の相談例の趣旨を維持し、以下の文言を使います。実際の導入実績ではなく、相談内容に応じた検討例として扱います。

#### タブ1：部門間の二重入力（初期表示）

相談タイトル：

> 同じ情報を、部門ごとに入力している

本文：

> 営業・製造・管理で別々の仕組みを使い、同じ情報を何度も入力しています。

確認すること：

> 情報の流れと、入力が重複する箇所を確認します。

比較する対応方法：

> システムの連携、一部業務の変更、全体の入れ替えを比較します。

まとめる内容：

> 変更する範囲と、先に取り組む業務

#### タブ2：AI導入の検討

相談タイトル：

> AIを使いたいが、どの業務に使うか決まっていない

本文：

> AIの導入を検討していますが、使う業務や確認方法が決まっていません。

確認すること：

> 対象業務、使う情報、人による確認が必要な箇所を確認します。

比較する対応方法：

> AIの利用、既存ツールの設定変更、業務手順の見直しを比較します。

まとめる内容：

> 試す業務の範囲と、効果の確認方法

#### タブ3：既存システムの見直し

相談タイトル：

> 今のシステムを、どこまで変えるか決められない

本文：

> 使いにくい箇所はあるものの、全体を入れ替えるべきか判断できていません。

確認すること：

> 利用部門、システム間のつながり、データ移行の制約を確認します。

比較する対応方法：

> 全体の入れ替え、段階的な変更、既存機能の追加を比較します。

まとめる内容：

> 残す部分、変更する部分、移行の順番

### SPと操作

- タブは3つを横並びにします。文字は意味のまとまりで2行にできます。タブの文字を極端に小さくしないでください。
- パネルは状況→確認→比較→まとめる内容の縦並び。PCの縦線は削除します。
- 全タブの切り替えが動作すること。選択状態を色だけに依存させないでください。
- `tablist`、`tab`、`tabpanel`、`aria-selected`、対応IDを整えます。キーボードでも切り替えられるようにします。
- 重要な情報をホバー・カード反転だけで表示しないでください。
- タブ間で不要な高さ固定をしないでください。長い内容が切れないようにします。

## 8. 支援内容：ページの中心となる4項目の図

### 見出しと補足

H2：

> 支援内容

補足：

> 相談内容に応じて、必要な支援を組み合わせます。

契約までの流れや、全項目を必ず順番に実施するサービスと誤解されないよう、この補足を残します。

### PCの外観

- 完成イメージと同様に、4つの領域が横につながる大きなステップ図を作ります。
- 背景は白、図の領域は淡い青、最終項目だけ淡いオレンジ。
- 最初の3つは濃い青の円形アイコン、最後はオレンジの円形アイコン。
- 領域の右端は山形の矢印。隣の領域との境界には白い区切りが入り、連続した流れに見える構造にします。
- 4項目は同じ幅。別々の角丸カードや、カード間に単純な矢印を置くだけの構成にしません。
- 円形アイコン→太い項目名→短い線→短い説明の順に並べます。
- 円形アイコンの直径はPC88〜112px、内側の白線画は44〜56pxを目安にします。
- 項目名はPC20〜22px・太字。説明は16〜18px、行間1.6〜1.7。
- 各項目の本文は左寄せ。本文幅を不必要に狭めず、完成画像程度の2〜3行を目安にします。
- 文章を白いカプセルの中に細分化しないでください。
- 各領域は矢印の先端分を除いた安全領域に文字を配置します。境界に文字を重ねないでください。

### 文言・アイコン

| 順番 | 項目名 | 説明 | アイコン |
| --- | --- | --- | --- |
| 1 | 業務と課題の整理 | 業務の流れと、困っている箇所を確認します。 | 虫眼鏡 |
| 2 | 投資と着手順の検討 | 効果・費用・実施の難しさを比較します。 | 天秤・比較 |
| 3 | システム・データの整理 | 既存システムと、情報の受け渡しを整理します。 | データベース |
| 4 | 実行と検証の計画 | 担当・進め方・効果の確認方法をまとめます。 | チェック付き書類 |

長い項目名は読みやすいまとまりで2行にできます。全項目のタイトル領域の高さをそろえます。

### 図形と配色の実装

- 各項目を意味のあるHTMLのリストとして作り、背景の山形は疑似要素・SVG・CSS等で描画します。
- `clip-path` を使う場合、背景レイヤーにだけ適用します。文字・フォーカス表示を切り取らないでください。
- 1〜3の背景は、淡青の濃淡にごく控えめなグラデーションを付けて構いません。円形アイコンもわずかな明暗で完成イメージの質感を再現します。
- 派手なガラス加工、強い光沢、ネオン、過剰な立体感を追加しないでください。
- 矢印の先端によって図全体が横にはみ出さないよう、全体幅を計算します。

### SP・タブレット

- 4項目のPC図を縮小して押し込まないでください。
- PC4列が読みやすく成立しなくなる幅で、4項目を縦につながる図に切り替えます。目安は1024px未満ですが、実際の文字幅で判断します。
- SPでは下向きの山形でつなぎます。アイコンを左、タイトル・説明を右に置くと縦長を抑えられます。
- 円形アイコンは56〜64px、説明は16pxを基本にします。
- 各項目の間には、つながりが分かる余白と形状を残します。
- 固定高さにして文字を切らないでください。
- この図は支援内容の全体を見せるため、カルーセルにはしません。

## 9. ご相談について・フッター

- 完成イメージのように、濃紺の横帯を置きます。
- PCは「ご相談について」・説明・問い合わせボタンを横並びにします。
- 説明：

> 検討中の内容や、現在困っていることをお聞かせください。

- ボタン：白背景、濃紺文字、「お問い合わせ」、右向きの小さな矢印。
- 問い合わせ先は既存の正しいURLを使います。架空のリンクを作らないでください。
- SPは縦並び。ボタンの高さは最低44px、十分なタップ領域を確保します。
- 共通フッターを引き継ぎます。完成画像にある過去の著作権年をそのまま転記しないでください。
