## 0. この資料の読み方・確度の凡例

- **[確認]** 公開ページのテキスト構造、リンク、画像アセットから確認できた事実。
- **[画像から判定]** 公開画像を直接確認できたデザイン上の特徴。ページ全体の配置を示すものではない。

- **[提案値]** 未採寸・解釈が分かれる項目のみ。オリジナル CSS の断定には使わない。

## 1. 全体像とデザインの方向性

### 1.1 ページの役割 [確認]

人事・組織課題を扱う6サービスを説明し、経営者・人事責任者が「自社の課題 → 支援領域 → 導入後の変化 → 進め方 → 問い合わせ」を理解するサービス総合ページ。

### 1.2 コンテンツのストーリー [確認]

1. 何の支援を行う会社かを示す（ブランド／総論）。
2. どの支援を見たいか選ばせる（ページ内メニュー・6サービス一覧）。
3. 各サービスの目的と対象課題を示す（概要・悩みの例）。
4. 実際に何を行うかを示す（「主な支援内容」の列挙）。
5. 改善前後の違いを見せる（Before／After。該当サービスのみ）。
6. 第三者のコメントと進め方を示す（お客様の声・5ステップ）。
7. 問い合わせ、関連事例、コラムへ接続する。

### 1.3 ビジュアルの核 [画像から判定]

- キーカラーは**黄みのあるオレンジ～朱色系のグラデーション**。柔らかいベージュ地の抽象イラストが6種類用意されている。
- オブジェクトは人物の写真ではなく、**図形・記号を大きく単純化した抽象イラスト**。各サービスの内容を直感的に分類する役割。
- アセットの背景は暖かみのある淡いベージュ。オレンジの表面に微細な粒子感／質感があり、単なるベタ塗りに比べて柔らかく見える。
- 6サービスの素材が同じテイストで揃っており、一覧を横断しても統一性が保たれる。
- 別途、白い「VOICE」「FLOW」などの大判タイポグラフィ風画像、オレンジの斜め矢印・大きなグラデーション装飾もある。
- **注意:** 原ページの各区画が暗色背景か、カード背景が白か、ボーダーが何pxかなどは画像だけでは判断できない。

### 1.4 デザイン言語を再構築する場合 [提案値]

> Warm Editorial × Modern Corporate。温かみあるニュートラル背景に強いオレンジを効かせ、見出しの大胆さと本文の読みやすさを両立する。イラスト自体を主要な装飾とし、不要な二重枠・多重シャドウを追加しない。

**全体の印象:** プロフェッショナル、前進するエネルギー、親しみ、明快さ。**避けるもの:** 汎用的な紺色SaaSカードの大量配置、単調な本文縦積み、過剰な角丸・影、すべて同じ行間、意味のない手動改行。

### 3.1 サービス01：人事評価制度の設計

**相談例（3件）:** 新規制度導入／制度の見直し／日々の運用効率化。

**主な支援内容（6件）:**
1. **等級制度の設計** — 組織像・採用・役割を踏まえた等級の整理。
2. **評価制度の設計** — 現場で運用・納得できる評価基準づくり。
3. **報酬制度の設計** — 給与帯・賞与・昇降給を一体的に設計。
4. **評価運用の仕組み化** — 研修、評価会議、目標設定の運用を整備。
5. **制度ハンドブック・社内説明資料の作成** — 運用ルールと社内説明を整える。
6. **導入後の運用伴走** — 現場からのフィードバックで改善・定着。

**Before/After（2組）:** 評価基準が曖昧・形式的 → 優秀層が定着する仕組み／報酬の競争力不足 → 市場水準を考慮した報酬設計。

### 3.2 サービス02：人材育成・マネジメント研修

**相談例（3件）:** 評価運用のばらつき／マネージャー層の成長／研修体系の新規整備。

**主な支援内容（4件）:** 評価者向け研修／目標設定と1on1の運用支援／新任管理職向け研修／役割・階層別研修の設計実施。

**Before/After（2組）:** 評価者間の判断差 → 納得できるフィードバック／評価をつけるだけの状態 → 育成につながる運用。

### 3.3 サービス03：採用戦略の企画と実行

**相談例（3件）:** 必要人材を採りきれない／採用を加速したい／選考の質と標準化。

**主な支援内容（5件）:** 採用計画とKPI／人物像・採用要件の言語化／採用チャネル設計／選考フローと面接官育成／入社後の受け入れ・立ち上がり支援。

**Before/After（1組）:** 場当たり的な採用 → 事業戦略から組み立てる人材獲得。

### 3.4 サービス04：人事領域のDX推進

**相談例（3件）:** 紙・Excelからの脱却／システム活用不足／人事データの一元化。

**主な支援内容（3件）:** 業務フローの整理／人事システムの比較・選定・導入／人材データベースと可視化の設計。

**Before/After（2組）:** データ散在 → 従業員情報の統合／導入ツールの形骸化 → データに基づく意思決定。

### 3.5 サービス05：IPO準備の支援

**相談例（3件）:** IPO準備の人員不足／制度・審査に必要な知識不足／社内への協力依頼が難しい。

**主な支援内容（2件）:** 労務監査への対応・リスク是正／関連社内規程の整備と運用支援。

**Before/After:** 公開ページの抽出コンテンツでは見当たらない。再現にあたって勝手に追加しない。

### 3.6 サービス06：その他のサービス

**概要:** 労務管理や人と組織に関わる周辺課題も対応領域とする。

**主な支援内容（2件）:** 労務規程・管理体制の整備（提携専門家との連携を含む）／組織のエンゲージメント調査と施策への接続。

**相談例・Before/After:** 他5サービスと同じ数の項目は確認できない。テンプレの穴埋めをしない。

### 3.7 お客様の声

2つのコメントの主題は、**支援後に自分で業務を進められるようになったこと／会社の一員のように現場に深く入って進めてもらえたこと**。直後に「導入事例を見る」導線がある。コメントの実名・顔・所属企業情報は抽出コンテンツに見当たらないため付与しない。

### 3.8 ご支援の流れ

| Step | 表示見出し | 訴求する内容 |

| 01 | 現状診断 | 現場・経営・制度の現状把握と課題の選別 |

| 03 | 詳細設計 | 評価項目、手順、報酬設計を具体化 |

## 4. コンポーネント分解・再現設計

> ※ここからのコンポーネント内部レイアウトは**再現用の設計提案**。元サイトのDOM順序・具体的な見え方を断定していない。画像の存在とコンテンツの並びは確認済み。

### 4.3 セクションの意味上の階層（提案）

```text
ServiceSection
├── SectionEyebrow: SERVICE
├── ServiceNumber: 01–06
├── ServiceHeading: h3相当
├── ServiceSummary: 概要テキスト
├── Concerns: 3点または省略
├── ResponsiveArtwork: desktop + mobileアセット

├── SupportList: 2～6要素

```

### 4.4 見た目を崩さない原則 [提案値]

- **サービス番号／タイトル／概要／補足の4段階**を混同しない。
- サービス固有のイラストを大きな識別要素とし、イラストの外に何重ものカード枠を足さない。
- `supportItems` が6項目のサービス01と2項目のサービス05・06で、無理にカードを等数に揃えない。
- Before/Afterは課題から効果への変化が**ひと組で完結**するように配置する。
- 長い本文はテキスト幅を抑える一方、右側に意味のない余白を作らない。空き領域は画像・対比表・余白の目的と対応させる。
- SPは**本文→本文→本文**の縦積みにならないよう、見出しとイラストの交互配置、論点の区切り、可読幅を優先する。ローカル MENU は非表示（第5.5章 [実測]）。

## 10. 原サイトCSSを厳密に採寸する方法

このレポートに不足している**実フォント名・実際のfont-size・色・行間・余白・画像表示寸法**は、原サイトをPCのChromeで開き、DevToolsを使用すれば取得できる。

2. F12 → 左上の要素選択アイコンを押す。
3. 見出し・段落・カード・画像などを選択。

5. **Elements → Styles** で `@media` 条件を探す。
6. Device toolbarで幅390pxを選び、同じ項目を採寸する。

### 10.2 一括採寸スクリプト

同梱の [`UP_Forward_style_capture.js`](./UP_Forward_style_capture.js) をChrome DevToolsのConsoleに貼り付けて実行すると、表示中のビューポート向けに主要要素の Computed Style・サービス画像の表示状態・`@media` 一覧を JSON でダウンロードできる。PC（1440）と SP（390）でそれぞれ実行し、本レポート第5章と突合する。2026-10-16 の自動採寸生データ: `up-forward-measure-pc-final.json` 等（同フォルダ）。

**注意:** ブラウザのコンソールへの貼り付けは、コードの内容を理解した上で行うこと。スクリプトは閲覧中のページの情報をローカルJSONに保存するだけで、サイトの内容を変更・外部へ送信しない。

## 11. Webデザイナー／実装担当への引き継ぎ指示

**制作順序:**

1. 見出し・コンテンツ・順序を先に再構築する。支援件数・改善例の数はこのレポートに一致させる。
