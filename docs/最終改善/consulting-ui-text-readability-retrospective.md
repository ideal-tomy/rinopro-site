## 1. 背景（何を改善したかったか）

- 経営層・DX担当向け LP として、**スマホでもプロフェッショナルに読める**状態にしたい。
- 特に「ご相談例」で、
  - **フォントカラー**（薄い／階層が分からない）
  - **テキストの羅列**（短い行が縦に並び、見出しと本文の区別が弱い）
  - **右側の不自然な余白**（2列比較レイアウトと改行の組み合わせ）
  が目立ち、参考モックや期待する見え方とのギャップが大きかった。
- 文言変更は一定期間禁止され、**構成・CSS・改行データ**での改善が主戦場だった。

## 2. 現状の問題点（2026-10-16 時点）

### 2.1 構造・情報設計

| 問題 | 内容 |
|------|------|
| **改行の二重化** | `ConsultingInteractions.tsx` の配列1要素＝1 `<span>` に、SP 向け `display: block` が乗り、**意図改行＋自動折り返し**が重なる（[改行レポート](./consulting-linebreak-layout-report.md) §2）。 |
| **左右2列の名残** | 一時期「問題｜検討」の2列＋矢印・薄青カードなどがあり、行数が揃わず**比較にならない空白**が出た。縦積みに変更後も、データ側の改行習慣が残っている。 |
| **視覚的階層の逆転** | ご相談例で、**お悩み（h3）が小さく**、**「AXEONが検討すること」側の青太字が大きい**期間があり、「誰の声が主役か」が不明瞭だった。 |
| **ブレークポイントの重複** | `899px` / `767px` / ファイル内の記述順により、**同じクラスに別メディアクエリの値が競合**し、期待した SP スタイルが当たらないことがある（[タイポ分析](./consulting-typography-mobile-analysis.md) §1）。 |

### 2.2 タイポグラフィ・カラー

| 問題 | 内容 |
|------|------|
| **本文の小型化（SP）** | 共有 `.body` / `.itemBody` などが **767px で 14px** になり、サイト方針（本文 15px 未満にしない）と矛盾する箇所がある。 |
| **行間のバラつき** | 同一カード内で `line-height: 1.45`（太字）と `1.85〜1.95`（本文）が混在。全站 `--line-height-body: 1.5` 試験後も、**セクション固有の上書き**が残る。 |
| **色の階層** | `--landing-body: #42516a` と `#334155` / `#132139` など**近いグレー・紺の使い分け**が多く、コントラストは足りても**「どれが見出しでどれが補足か」**が弱い。 |
| **極小文字** | ヒーロー工程図 SP で **12px** 本文があり、周辺（15〜16px）と比べて読みづらい（タイポ分析 §2.4）。 |
| **デザインシステムの罠** | リポジトリ全体で `text-base` が**文字色（ほぼ白）**と衝突するルールがある一方、LP は CSS Modules の直書き色が多く、**トークン統一が効いていない**。 |

### 2.3 開発・検証環境（UI確認を妨げた要因）

| 問題 | 内容 |
|------|------|
| **localhost:3000 の取り違え** | `C:\Users\ryoji\node_modules` の **別 Next 15 プロジェクト**が 3000 を占有し、rinopro-site（Tailwind 4 + `@tailwindcss/postcss`）と混同。画面上は `@tailwindcss/postcss` 不足の Build Error。 |
| **Vercel デプロイ** | `package-lock.json` の integrity 不整合・Sanity 依存のネストなどで install が不安定（本番確認が遅れた）。 |

これらは「デザインが悪い」というより、**正しいビルドで目視できない時間**が長く、改善の手戻りを増やした。

## 4. 「AIの適当な出力で終わった」原因の整理

ここでは、**ツールの性格**と**依頼・合意の形**の両方を書く。ユーザー体験として「また別の見た目になったが読みやすくはならない」が繰り返された理由。

### 4.1 ゴールと評価基準がセッションごとにブレた

- 「文言は変えない」「参考画像の構成だけ」「モックに合わせる」「AI丸出しでプロ UI」など、**優先順位が途中で入れ替わった**。
- AI は都度「直近の指示」に最適化し、**前セッションの合意（PLAN・モック差分）を一貫した受け入れ基準として保持できなかった**。

### 4.2 見た目のパラメータ調整に偏り、読みやすさの因を一本化しなかった

- フォントサイズ・色・カード枠・番号付けなど**表面的な UI パターン**は何度も差し替わった。
- 一方で可読性の本丸である
  - **配列 span + `display: block`**
  - **`word-break: keep-all` と狭い列**
  - **SP 14px 本文**
  は、構造レポートで指摘されたあとも、**一括リファクタ（データモデル or CSS の単一ルール）まで踏み込めなかった**。

### 4.3 実機・正しい dev サーバーでの確認が不十分なまま提案が進んだ

- 3000 番の**別プロジェクト**、`.next` 破損、`npm ci` の EPERM などで、**rinopro-site の最新 CSS を安定して見られない**状態が続いた。
- AI は「おそらくこう見える」で CSS を積み増しし、**ユーザー目視とのズレ**（モック不一致）がフィードバックとして返ってきた。

### 4.4 モック／参考と実装の差分を最初にピクセル単位で固定しなかった

- 参考は「雰囲気」レベルで渡され、**タイポスケール（サイズ・ウェイト・色・行間・余白の表）**が合意されていなかった。
- そのため AI は都度**別解のカード UI**を生成し、ユーザーからは「AI のテンプレ感」「適当なカードデザイン」と受け取られた。

### 4.5 変更範囲が広く、ロールバックしやすい単位にならなかった

- ご相談例・工程図・roles・line-height 全站・デプロイ lock が**同一ブランチ上で混在**。
- 「読みやすさだけ戻す」が難しく、**改善した／悪化したの切り分け**がユーザー側で負担になった。

### 4.6 プロジェクトルールはあるが、LP 固有 CSS がルールから逸脱している

- 明背景＋濃色文字、`text-base` 禁止、日本語折り返し（意味の切れ目）など**ルールは明確**。
- 実装は `consulting-page.module.css` に**歴史的な SP 上書き**が残り、AI は「既存に合わせる」ことで**悪いパターンを温存**した。

## 5. まだ「読みやすい」と言い切れない理由（要約）

1. **改行モデル**（配列＋block＋keep-all）が、モバイルで「短い行の羅列」を再現しやすい。  
2. **タイポスケール**がセクション・ブレークポイントごとにバラけ、一つの rhythm に統一されていない。  
3. **色はコントラスト足りても階層が弱い**（ラベル・お悩み・検討・本文の役割が色だけでは判別しづらい）。  
4. **検証環境の混乱**で、改善の正誤がすぐ共有できなかった。

## 6. 次にやるなら（レポート上の提案・未実装）

AI に任せる前に、人間側で固定するとよいもの。

| 項目 | 内容 |
|------|------|
| **タイポ表** | h2 / リード / お悩み / 検討見出し / 本文 / ラベルの **px・weight・color・line-height** を 375 / 768 / 1200 の3幅で1枚に固定。 |
| **改行ポリシー** | 配列をやめるか、`display: block` を廃止し **`<br>` または意味単位の1行文字列のみ**に統一（`lp-japanese-wrap` ルール準拠）。 |
| **SP 本文** | 14px 指定を 15px 以上に揃える（共有 `service-landing-shared` の 767px ルール見直し）。 |
| **検証** | 常に rinopro-site の `npm run dev` の URL（3000 占有時はプロセス停止）でスクショ比較。 |
| **コミット粒度** | 「ご相談例タイポのみ」など **1テーマ1コミット**で、AI 出力の巻き戻しを容易にする。 |

## 8. 結論

UI 改善は**何度も着手したが**、フォントカラーとテキスト羅列の可読性については、**構造（改行・階層・ブレークポイント）を先に固定せず、カードやサイズの差し替えを繰り返した**ことが主因である。AI は各ターンで「それらしい」CSS と構成を出したが、**合意されたタイポスケール・実機確認・単一の改行ルール**が欠けたため、ユーザーからは**適当な出力で終わった**ように見えた。

本レポートと既存の2調査 MD をセットにすると、「何が悪くて、何を触って、なぜ満たせなかったか」を後続の人間／AI が同じ前提で再開できる。
