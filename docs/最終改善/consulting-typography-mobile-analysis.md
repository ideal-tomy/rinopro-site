## 3. タイトルと本文の余白（margin / padding）

### 3.1 セクション見出し → リード文

| 設定 | 値 | 場所 |
|------|-----|------|
| `.page .body` の上余白 | **margin-top: 24px** | `service-landing-shared` |
| 連続 `.body` | 2段落目以降 **margin-top: 16px** | 同上 |
| `.page .note` | **margin-top: 28px** | 資料セクションの注釈 |

SP では `.section` の **padding-block: 72px**（PC 116px）でセクション全体の縦余白は確保されているが、**見出し直下の 24px** は PC/SP 共通。

### 3.2 ご相談例セクション

| 区間 | PC | SP（≤899px） |
|------|-----|--------------|
| リード `.body` → カードリスト `.examples` | `padding-top: **56px**`（リスト側） | `padding-top: **28px**` |
| カード間 | 罫線で区切り（`padding-block: 40px`） | `gap: **14px**`（flex カラム） |
| カード内 | — | `padding: 16px 14px 14px` |
| ラベル → 問題見出し | `margin-top: **10px**`（PC） | `margin-top: **4px**`（SP） |
| ラベル → 検討見出し | `margin-top: **10px**` | `margin-top: **4px**` |
| 上部比較エリア → 説明 `.exampleBody` | `margin-top: **12px**` | `margin-top: **12px**` + `padding-top: **12px**` + **上罫線** |

**読みにくさとの関係**

- SP ではラベルと太字の間が **4px** と詰まり、ラベル（12px）と見出し（15〜17px）が**1塊**に見える。
- 比較エリアと説明文の境は罫線で明確だが、その直上に**すでに折り返しだらけの太字**があるため、視覚的には「文字の塊が二段」に感じる。

### 3.3 モバイル用 h2 青ライン（≤899px）

```css
.consultingMobileSection h2::before,
.resultSection h2::before {
  margin-bottom: 14px;
}
```

見出しテキストの**上**に 3px バーが付く。`.heading` 自体の `margin-top: 0` のため、**バー → 見出し → 24px → 本文** の縦リズムになる。

### 3.4 ご相談例カード内レイアウトが作る「実効余白」

SP の `.exampleTop` は **3 列グリッド**（左列 `1fr` | 矢印 24px | 右列 `1fr`）。

さらに左列 `.exampleProblemCol` は **アイコン 34px + テキスト列** の2列。

→ **テキストが入る幅が極端に狭い**（次章）。余白の数値より、**列分割**が「詰まって見える」主因。

## 5. スマホ表示の改行（マークアップ + CSS）

### 5.1 意図的な改行（データ）

`ConsultingInteractions.tsx` の `problem` / `focus` は **文字列配列**。

- 各要素は `<span style="display: block">`（`.exampleProblem span` / SP 時 `.exampleFocus span`）で**強制改行**。
- `problem` 内の `|` は `<wbr />` に変換（例: `どの業務に使えばよいか|わからない。`）。

**効果**: デザイン上の「意味の切れ目」は守れるが、**列幅が狭いと wbr 前後でもさらに自動折り返し**が重なる。

### 5.2 CSS による折り返し制御

```css
.exampleProblem span,
.exampleFocus span {
  word-break: keep-all;
  overflow-wrap: anywhere;
}
```

| 指定 | 挙動 |
|------|------|
| `word-break: keep-all` | 日本語は単語境界を保ちたいが、列が狭いと**1文字行**が出やすい |
| `overflow-wrap: anywhere` | どこでも改行可 → **keep-all と相反する方向**の折り返しも起きうる |
| `.page .heading` など `word-break: keep-all` | セクション h2 も長い1行を避けられず、SP で行数増 |

### 5.3 レイアウト起因の改行（最重要）

**概算（幅 375px 端末、767px 以下の container `calc(100% - 12%)`）**

1. コンテンツ幅 ≒ 330px  
2. カード左右 padding 28px → 内側 ≒ 302px  
3. `.exampleTop` 3 列（`1fr` + 24px + `1fr`、gap 6px）→ **各テキスト列 ≒ 130px 前後**  
4. 左列はさらにアイコン 34px + gap 8px → **問題文の列 ≒ 88px**

→ **「同じ情報を、」「何度も入力している。」** が縦に細切れになるのは、フォントサイズ以前に**列設計**によるもの。

矢印列は `align-items: center` で、左右の**行数が揃わない**とき、ラベル位置もバラけて「ぐちゃつき」に見える。

### 5.4 その他

- CTA 見出しは `<wbr />` で「計画づくりだけでも、」の後を改行許可（`shared.lines` + span）。
- 資料注釈「※ 右は構成例です」は SP でも横並び split が縦積みになり、**「右」が画面上の位置と一致しない**（文言は変えていないため、UX 上の違和感のみ）。

## 6. 「ぐちゃぐちゃ」になる原因のまとめ（現在の設定ベース）

1. **899px 以下で PC 向け「左右比較」レイアウトを維持**  
   - 3 列グリッド + 左内側の icon 列で、実効文字幅が **約 90〜130px** まで落ちる。

2. **太字見出しのサイズと行間が、本文と別レンジ**  
   - カード内 15〜17px / line-height 1.45 vs 本文 15px / 1.6〜1.85。

3. **改行の二重管理**  
   - データの `display: block` + `keep-all` + `overflow-wrap: anywhere` + 狭い列の自動折り返し。

4. **メディアクエリの重複**  
   - 767px と 899px の両方が `.examples` に触れる。どちらが勝つかは記述順に依存し、**意図した clamp がブレる**可能性。

5. **本文色の不統一**  
   - `#42516a` / `#334155` / `#111` が混在し、同じカード内でも説明だけ別グレー（SP）。

6. **ラベルと見出しの余白が SP で 4px**  
   - 情報階層（ラベル → 見出し → 本文）が視覚的に分離しきれない。

7. **ページ全体は 767px で 14px 本文**、一方カード太字は 15px 前後  
   - **サイズ階層が逆転**し、どこが「見出し」か判別しづらい。

8. **ヒーロー工程図だけ 12px 本文**  
   - ファーストビュー付近のタイポがページ他部と乖離。

## 8. 改善案（文言変更なし前提）

優先度は **効果 / 実装コスト** のバランスで記載。コピーは変えず、**型・トークン・CSS の整理**が中心。

### 8.1 最優先：SP のご相談例レイアウトを変える（899px 以下のみ）

| 案 | 内容 | 期待できる効果 |
|----|------|----------------|
| **A. 縦ストーリー** | 上: ご相談（アイコン+問題）→ 下矢印 → 検討（青太字）→ 全幅説明 | 列幅がコンテナ幅に戻り、**意図した span 改行だけ**が効く |
| **B. 比較は1行ラベルだけ横並び** | 「ご相談｜何を検討するか」は小ラベル、太字は**それぞれ全幅1ブロック** | モックの「比較」の意味を残しつつ幅を確保 |
| **C. 現レイアウト維持** | `grid-template-columns` を `1fr` のみに（矢印はブロック間） | 変更最小だが、縦長になる |

**推奨**: **A または B**。現状の 3 列 + icon ネストは、文言を変えない限り**構造的に折り返しが増える**。

### 8.2 タイポの統一（トークン化）

1. 本文グレーを **1色に固定**（例: すべて `--landing-body` `#42516a`。SP だけ `#334155` にする上書きを削除）。  
2. SP 本文の下限を **15px** に揃える（`767px` の `.body` / `.itemBody` **14px → 15px**、工程図 **12px → 14〜15px**）。  
3. カード内太字は **16px / line-height 1.5〜1.55** にし、本文（15px / 1.65）と**階層差を数値で固定**。  
4. ラベルは **12px のまま**でよいが、見出しとの間を **margin-top: 8px** 程度に統一。

### 8.3 行間ルールの単純化

- **見出し系**: line-height **1.45〜1.5**  
- **本文**: line-height **1.65〜1.75**（1.95 は PC のみでも可）  
- 同一カード内で **1.45 と 1.85 を混在させない**

### 8.4 改行まわり

- `overflow-wrap: anywhere` をカード太字から外し、**`overflow-wrap: break-word` または normal** に。  
- データの `display: block` は維持し、**横並び比較をやめる**前提で意味の切れ目を活かす。  
- `|` + `<wbr />` は縦レイアウト時のみ有効なので、横並び廃止とセットで効く。

### 8.5 メディアクエリ整理

- コンサル SP 用は **899px 1本**に寄せ、767px 内の `.examples` 上書きを**削除または 899px に統合**（clamp の競合解消）。  
- 「モバイルタイポ」は `service-landing-shared` の 767px ブロックと `consulting-page` の 899px ブロックを**一覧表で対応付け**してから変更する。

### 8.6 余白

- セクション h2 → `.body` は SP でも **20〜24px** を維持でよい。  
- カード内ラベル → 太字は **8px**、太字ブロック間は **12〜16px**、説明への境界は **罫線 + 16px** で統一。

### 8.7 資料・CTA（文言そのまま）

- 注釈「右」は CSS では直せない。**レイアウトで資料を下に置く現状**は維持し、将来文言変更可能になったら「下の構成例」等に。  
- CTA は色の統一（`#334155` vs `#42516a`）だけで十分改善することが多い。

### 8.8 進め方（デザイン疲れ対策）

1. **ご相談例 SP だけ A 案で1パターン実装** → 375px スクショで判断（他セクションは触らない）。  
2. 良ければ **トークン統一（8.2）** をページ全体に横展開。  
3. モック完全一致は、**375px + 実コピー入り**のワイヤー1枚があるとき再開。
