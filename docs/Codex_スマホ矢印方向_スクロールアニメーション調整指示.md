# Codex実装指示｜スマホ矢印方向・スクロール表示アニメーション調整

対象:
- 現在実装済みの「支援範囲」などのフロー表示
- ページ内のスクロール表示アニメーション
- PC / スマホ両方

目的:
- スマホ表示では、縦方向のレイアウトに合わせて矢印も下向きにする
- 現在のスクロール表示アニメーションを、もう少しゆっくり・はっきり認識できる速度へ調整する
- デザイン、掲載内容、PCレイアウトは変更しない

---

# 0. 最重要ルール

今回変更するのは以下だけです。

1. スマホ表示時の矢印方向
2. スクロール表示アニメーションの速度
3. アニメーションの発火タイミング
4. staggerの間隔

以下は変更しないでください。

- 掲載内容
- テキスト
- カードデザイン
- 配色
- PCレイアウト
- セクション構成
- CTA
- 画像
- アイコンの基本デザイン

---

# 1. スマホ表示の矢印を下向きに変更

現在スマホではコンテンツが縦方向に並んでいるにもかかわらず、
PC用の横向き矢印がそのまま表示されています。

PC:

左 → 右

スマホ:

上
↓
下

となるように変更してください。

---

# 2. 対象箇所

添付画像で確認できる、

- 「経営の方針 / 現場の状況」→ AXEON
- AXEON → 「社内で検討するための計画」

の接続部分。

スマホでは両方とも下方向へ進む表示に変更してください。

---

# 3. PC表示

PCでは現在の横方向接続を維持してください。

```text
経営の方針 ─┐
             ├─→ AXEON → 計画
現場の状況 ─┘
```

PCの矢印や接続線は変更しない。

---

# 4. スマホ表示

スマホでは縦方向の流れにする。

```text
経営の方針

現場の状況

      ↓

    AXEON

      ↓

社内で検討するための計画
```

横向き矢印や横方向の合流記号は表示しない。

---

# 5. PC用矢印を単純回転しない

可能であれば、

- Desktop Connector
- Mobile Connector

を分けてください。

スマホでは、
PC用の複雑な横方向合流線を90度回転するのではなく、
シンプルな下向き矢印または縦線＋矢印を使ってください。

理由:
スマホでは2つの入力カード自体が縦積みになるため、
PC用接続線を回転すると意味が分かりにくくなるためです。

---

# 6. スマホ矢印の見た目

- blue
- 細め
- 中央配置
- 上下余白を取りすぎない
- アイコンサイズ 28〜36px程度
- 強い発光なし

AXEONカードと次のカードの間に、
自然な余白を確保して配置してください。

---

# 7. スクロールアニメーションを全体的に少しゆっくりにする

現在のscroll revealは動作していますが、
表示速度が速すぎて、

「ふわっと表示された」

と認識する前に表示が完了している要素があります。

現在の演出を維持したまま、
もう少しゆっくり、はっきり分かる速度に調整してください。

---

# 8. duration

現在の値を確認したうえで、
基本durationを以下に近づけてください。

## 通常コンテンツ

```text
700〜800ms
```

推奨:

```text
760ms
```

## 大きなカード / セクション主役

```text
780〜900ms
```

推奨:

```text
820ms
```

## 小さな補助要素

```text
600〜700ms
```

1秒以上の遅い演出にはしない。

---

# 9. 移動量

fadeだけに近い状態では変化が分かりにくいため、
以下を基本にしてください。

```css
opacity: 0;
transform: translateY(18px);
```

↓

```css
opacity: 1;
transform: translateY(0);
```

目安:

```text
translateY 16〜22px
```

大きすぎる移動は禁止。

---

# 10. easing

自然に止まるease-out系を使用してください。

推奨:

```css
cubic-bezier(0.22, 1, 0.36, 1)
```

または既存animation libraryの自然なease-out相当。

linearや強いease-in-outは避ける。

---

# 11. staggerを少し広げる

複数カードがほぼ同時に表示されている場合は、
表示差を少し大きくしてください。

目安:

```text
120〜160ms
```

例:

```text
カード1
↓ 140ms
カード2
↓ 140ms
カード3
```

ただし5枚以上ある一覧では、
全体が遅くなりすぎないよう100〜120ms程度でもよい。

---

# 12. 発火タイミングを必ず確認

今回重要なのはdurationだけではありません。

現在、

「ユーザーがその要素を見る前にanimationが開始している」

可能性があります。

IntersectionObserver / viewport判定を確認してください。

画面下部に少し入っただけで発火する設定にはしない。

---

# 13. IntersectionObserverの場合

目安:

```js
threshold: 0.18〜0.25
```

または、

```js
rootMargin: "0px 0px -10% 0px"
```

程度。

要素が実際にviewportへ入ってから、
animationが認識できるタイミングで開始してください。

---

# 14. Framer Motionの場合

`whileInView` を使用しているなら、

```js
viewport={{
  once: true,
  amount: 0.2
}}
```

程度を基準に調整してください。

現在の `amount` が極端に小さい場合は修正してください。

---

# 15. 一度だけ実行

スクロールで画面外へ出るたびに
非表示へ戻さないでください。

一度表示されたコンテンツはそのまま表示する。

```text
once: true
```

相当の動作を維持してください。

---

# 16. PC / SPの速度差

スマホは縦スクロール量が多いため、
PCと完全に同じstaggerにすると重く感じる可能性があります。

目安:

## Desktop

```text
duration: 760〜820ms
stagger: 120〜160ms
```

## Mobile

```text
duration: 680〜760ms
stagger: 80〜120ms
```

ただし現在よりは明確にゆっくり表示する。

---

# 17. 「支援範囲」の表示順

スマホでは以下の順序を守ってください。

1. 経営の方針
2. 現場の状況
3. 下向き接続矢印
4. AXEONカード
5. 下向き矢印
6. 社内で検討するための計画
7. 計画カード内部の各項目

すべて同時に表示しない。

# 18. 成果カード内部

「社内で検討するための計画」が表示された後、

- 変更する範囲
- 着手する順番
- 担当と進め方

を、

```text
100〜140ms
```

程度ずつ遅らせて表示してください。

カード本体と内容全部を同時に出さない。

---

# 19. ページ全体のscroll reveal

現在実装済みの各セクションについても、
速すぎる箇所がないか確認してください。

対象例:

- Hero内の要素
- カードグループ
- セクション見出し
- タブコンテンツ
- CTA
- PROCESS
- 相談例
- 会社紹介などの各セクション

全要素を同じdelayにするのではなく、
意味のまとまりごとに順番表示してください。

---

# 20. 禁止事項

- PCの矢印方向を変更する
- 全arrow iconを一括でrotateする
- スマホでも横方向の意味を残す
- animationを1秒以上にする
- 大きなtranslate
- bounce
- 強いscale
- blurを強く使う
- scrollのたびにanimationを繰り返す
- 新しいanimation libraryを追加する
- 掲載内容やデザインを変更する

---

# 21. prefers-reduced-motion

現在対応済みなら維持。

未対応なら、

```css
@media (prefers-reduced-motion: reduce)
```

では、

- translateを停止
- staggerを停止
- 即時表示または軽いopacity transition

にしてください。

---

# 22. 実装前確認

変更前に以下を確認してください。

1. 現在のarrow / connector実装
2. PC / SPで同じSVGやiconを使っているか
3. animationの共通component / hook / CSS
4. duration
5. delay / stagger
6. IntersectionObserver設定
7. Framer Motion等のviewport設定
8. responsive breakpoint

既存の共通animation設定がある場合は、
個別ページだけにハードコードせず、
必要に応じて共通設定側を調整してください。

ただし他ページへの影響を必ず確認すること。

# 24. 完了条件

今回の完成条件は以下です。

- PCのフローは横方向のまま
- SPのフローは上→下へ統一
- PC用接続線を単純回転した不自然な見た目になっていない
- 「ふわっと表示」が目で認識できる
- animation発火が早すぎない
- durationが短すぎない
- staggerが自然
- 画面表示が重く感じない
- 一度表示したら再アニメーションしない
- reduced motion対応
- デザイン・文章・構成は変更していない

# 最終意図

今回の目的は、
animationを派手にすることではありません。

現在:

```text
スクロール
→ ほぼ既に表示されている
```

から、

```text
スクロール
→ セクションが画面に入る
→ 少し下から自然に表示
→ 次の要素が少し遅れて表示
```

という、
ユーザーが自然に認識できる表示速度へ変更してください。

またスマホでは、
視線が上から下へ移動するため、
接続矢印も必ずその方向に合わせてください。
