# AXEON「相談例」セクション 実装指示

## 目的・変更範囲

コンサルティング詳細ページの「相談例」セクションを修正してください。
リポジトリ：https://github.com/ideal-tomy/rinopro-site

現在のコードから対象URLと部品を特定してください。変更対象は相談例と、その表示に必要なCSS・データです。周囲のHero、図解、支援内容、問い合わせ導線は維持します。

完成形：
- PC：3枚のカードを横並びにせず、左右対応の横長行を3行並べる。
- SP：3件をカード化し、横スクロールで表示する。
- PC・SPともタブを撤去する。
- 最初に困りごと、次に、最後に確認・比較方法を読める強弱にする。

添付の現在の画面は問題の確認用です。古いタブ付き構成を再現しないでください。

## 1. 事前確認

- 現在のブランチと未コミット変更を確認し、ユーザーの作業を上書きしない。
- 相談例のデータ、タブ、横スクロール、表示アニメーションの実装を確認する。
- 修正前のPC・SP画面を記録する。
- 変更するファイルと方針を短く示してから、実装・検証まで進める。

## 2. セクション冒頭

小さなラベル：

主見出し：

まだ決まっていなくても。

説明：
今の業務や困りごとを確認し、対応方法と、先に取り組む範囲を整理します。

ラベルより主見出しを大きくします。
見出しと本文は左揃え。
見出しは上記の意味単位を基本にし、375pxでも横にはみ出さないよう調整します。
本文には幅合わせの強制改行を追加しません。

## 4. PC：左右対応の3行

同じ幅の横長行を、上から3行並べます。
「3列カード」「タブで1件ずつ切り替えるパネル」にはしません。

各行の左：
- 小さな分類ラベル
- 大きく太い困りごと

各行の右：
- 小さな「」ラベル
- 整理する内容
- 通常の本文サイズの確認・比較方法

基準：
- 左右は約42：58を出発点に調整。
- 列の間隔は32px程度。
- 行の上下余白は28〜36px程度。
- 行と行を薄い横線で区切る。
- 大きな囲み枠、角丸カード、強い影は使わない。
- 右の結論は青い文字等で強調するが、左の困りごとより大きくしない。
- 右の説明領域をボタンのようにしない。
- 行をクリック可能なように見せない。
- 外側の左右位置は周囲のセクションと揃える。

デザイン上は左右の一覧ですが、HTMLのtableにする必要はありません。
各相談例を1つの意味ある項目として実装し、SPでも同じ情報が読める構造にします。

## 5. SP：タブなしの横スクロール

3件を、横スクロールのカードとして表示します。
縦に3枚積みません。

カード内の順序：
1. 小さな分類ラベル
2. 大きな困りごと
3. 淡い青の領域に「」と結論
4. 確認・比較方法の補足

基準：
- 左右の外側余白は20px程度。
- カードは横スクロール領域内幅の85〜90%程度を出発点に調整。
- カード間隔は12〜16px程度。
- 右側に次のカードが少し見え、横へ送れることが分かるようにする。
- カード内部の左右余白は16〜20px程度。
- 外枠は薄い線、角丸は控えめ、影はなし〜ごく弱く。
- 全文を表示し、行数制限や省略記号で隠さない。
- 上端を揃え、3件を表示するのに必要な自然な高さでカードの高さを揃える。
- 巨大な固定高さで余白を増やさない。
- 反転、アコーディオン、詳細表示の追加操作は作らない。
- 自動送りをしない。

横スクロールは既存の安定した実装、またはネイティブスクロールを優先します。
必要ならscroll-snapで1件ずつ止まるようにします。
新しいカルーセルライブラリは原則追加しません。

現在位置は下部の小さなドット1種類に統一します。
ドットを移動ボタンにする場合は、押しやすい領域と読み上げラベル、現在位置の表示を持たせます。
スワイプでも現在位置が更新されることを確認してください。
旧タブと「3 / 3」等の重複する操作・表示は撤去します。

## 6. 視覚的な優先順位

困りごと ＞ 整理する内容 ＞ 補足 ＞ 分類・ラベル・注記

目安：
- PC困りごと：24〜28px程度、太字
- SP困りごと：22〜24px程度、太字
- 整理する内容：18〜20px程度、太字
- 本文：16px程度、行高1.7〜1.8
- 分類・ラベル：12〜14px程度
- 見出し：ほぼ黒
- 本文：濃い色。薄いグレーにしすぎない
- 青：現在のAXEONのブランド色を使用

既存フォントを維持し、実画面の収まりで調整してください。
この数値を理由に周囲のデザインを変えません。

「相談の状況」「確認すること」「比較する対応方法」「まとめる内容」を、
現在のようにすべて同じ強さで見せないでください。
確認と比較は1つの補足にまとめます。
検索・グラフ・書類のアイコンを繰り返す表示と、装飾用の矢印は外します。

このセクションに新しいCTAは追加せず、既存のページ共通問い合わせ導線を維持します。

## 7. スクロールと表示演出

- 表示演出はセクション単位で一度だけ。
- 見出し・本文・カードへ別々の遅延フェードを重ねない。
- 横スワイプや位置更新で演出を再実行しない。
- 横移動でカードの縦位置や領域の高さが変わらないようにする。
- 表示演出と横移動が同じtransformを上書きしないようにする。
- 横スクロール領域から始めた縦スワイプでも、ページを縦スクロールできる。
- 動きを減らす設定では、演出なしで内容を表示する。

タブの状態管理やイベントを撤去した後、不要な依存や参照を残さないでください。
共通部品は利用元を確認し、他セクションのタブまで削除しないでください。

## 8. 検証

SP：375 / 390 / 430px
PC：1280 / 1440px
切り替え幅の前後とタブレット幅も確認します。
2列が成立しない中間幅では、無理にPC配置を押し込まないでください。

確認事項：
- PCで3件が縦の3行になっている。
- SPでタブなしの横スクロールになっている。
- 困りごとが最初に目に入り、整理する内容が続いて読める。
- 3件すべての本文が表示されている。
- 注記が1回だけ表示されている。
- 自動送り・反転・不要なクリック操作がない。
- 初回表示中と表示完了後、両方で横スワイプできる。
- 縦ずれ・高さの変動・不自然な横はみ出しがない。
- PCの見出し・本文の位置が周囲のセクションと揃っている。
- 見出し末尾の孤立、句読点の孤立、重要な熟語の不自然な分割がない。
- キーボード操作・フォーカス表示・位置表示が機能する。
- 前後のセクションと既存リンクが壊れていない。

overflow-x: hiddenで崩れを隠さないでください。
iPhone Safari実機と、PCのスマホ幅プレビューは区別して報告します。
必要なビルド等のチェックを実行してください。
